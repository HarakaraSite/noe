The `run_js` tool executes an ES module with top-level await in a fresh owned JavaScript runtime. Global variables, module state, and owned runtime resources do not persist between calls. Relative imports from the virtual entry resolve from the execution's configured working directory; file-backed modules resolve them from their importing module. import.meta.url is the module's encoded file URL or final HTTP/HTTPS URL. The virtual entry uses a synthetic <virtual-entry>.mjs file URL under its cwd; that source file need not exist.

Agent helpers are not implicitly bound; they are ES module exports from `noe:agent`. A default export supplies the result's data field. A default Promise or thenable is awaited, but nested Promises are not deeply awaited and default functions are not called. A final expression supplies no data; an explicit null supplies data: null. The resolved value follows JSON.stringify rules, so root undefined, functions, Symbols, BigInt, cycles, and throwing conversions can fail serialization. Execution and serialization failures do not roll back completed file writes or external effects. Separate tool calls may run concurrently and have no execution-order guarantee.

Available APIs depend on the selected profile. The `noe:docs` module provides the version-matched reference through docs(), docs(topic), or docs(topic, member); the CLI equivalent is noe docs [topic [member]]. Its catalog includes APIs that a profile may not enable, and Node.js API compatibility is partial. Host-specific runtime facts report HTTP/HTTPS ESM URL import availability. Remote modules resolve relative imports against their own URLs; URL imports and fetch are independent capabilities.

A run_js result contains stdout, stderr, exitCode, reason, and optional data and diagnostics. stdout/stderr contain actual writes; exception details are separate diagnostics. The complete model-facing JSON has a default 65536-byte budget, including metadata, JSON escaping, data, diagnostics, and hook results. An initial line-comment block can set `// @noe: {"outputBytes": 131072}`; valid values are integers from 1024 to 262144 bytes. This setting also controls stdout/stderr capture. Truncated streams retain their beginning and end with omission counts. Oversized model-facing results contain incomplete outputPreview text, outputLimit byte counts, and original execution status. outputPreview is not complete JSON, and later budget changes cannot restore bytes omitted during capture.

NOE_CONTEXT_STATUS is a runtime-generated user message in conversation history, not human steering. It may contain factual notices of recovered hook failures. Such failures do not themselves stop a task or require another model request. TaskOutcome.hookFailures preserves them, including failures after the final response. includeAnswer:false retains these records; read_task_result reads only the unchanged answer.

The `noe:agent` module exposes run_agent, spawn_agent, observe_agent, queue_agent, wait_task, wait_tasks, read_task_result, steer_agent, cancel_task, stop_agent, and list_models. Operations are checked against the current execution's ownership scope. Root launches require provider, model, and effort; a child can inherit them from its launching run. spawn_agent and queue_agent return accepted command identifiers. wait_task observes one command's retained result, cancel_task cancels one command, and stop_agent stops an instance and its remaining work.

wait_tasks accepts a set of {agentId, commandId} references and returns {reason: "completed" | "steer", runId?, completed: [{agentId, outcome}], pending: [{agentId, commandId}]}. A steer return leaves children running. Guidance remains pending until the parent's next model boundary, which cannot occur while its run_js call is still executing. wait_task is completion-only; combining completion-only waits does not provide steer-aware waiting. Request or owner cancellation rejects rather than returning steer.
