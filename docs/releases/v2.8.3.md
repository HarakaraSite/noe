# NOE v2.8.3

This release separates built-in execution/API facts from user-controlled
behavioral guidance. Go 1.27.2, go-quickjs v0.29.0, go-intl v0.8.0, public
APIs and selected dependencies are unchanged.

## User-controlled instructions

- The CLI no longer injects an embedded behavioral policy. Autonomy,
  approval, language, tool/model selection and work procedures can be
  chosen through common and workspace instruction files.
- The repository supplies editable behavior.md and tool-use.md alongside
  its development, delegation and JS-tool guidance. These are ordinary
  external files, not a hidden fallback or content recreated by the binary.
- Removing or replacing an external instruction changes the guidance for
  newly started instances. Existing instances retain their instruction
  snapshot; new children load current files independently.
- Composition remains runtime/API facts, common files, workspace files,
  then explicit config.system. A custom Go host still controls its own
  HostConfig.Instructions and optional HostConfig.Policy.

See the [instruction guide](../instructions.md) for locations, ordering
and lifetime. Existing behavioral preferences must be kept in external
files if they are still wanted; an empty instruction directory no longer
receives NOE's former fixed policy automatically.

## Factual runtime descriptions

- Built-in agent facts describe isolation, serialization, ownership,
  capability availability, output budgets and steer-aware waiting.
- Context-status and truncated-output notices retain their execution
  information without embedding work-planning instructions.
- The run_js tool description is shorter and points to the bundled
  version-matched contract. An operation comment is an external preference,
  not a runtime syntax requirement.
- Workspace lint guidance no longer declares agent helpers as implicit
  globals; snippets and scripts import them from noe:agent.

No output limits, serialization rules, capabilities or agent ownership
semantics are changed by this instruction cleanup.

## Validation and distribution

Affected agent, instruction-reader, managed-runtime, bundled-doc and
executor package tests passed, including instruction absence, replacement,
removal, per-instance snapshots, child loading and context-history behavior.
The actual CLI run/eval instruction-file E2E passed. Development Staticcheck,
changed-JavaScript lint, formatting and diff checks also passed.

Release preparation reuses this implementation evidence. The unchanged
lightweight CI builds six CGO-free binaries, creates SHA256SUMS and publishes
the immutable tag. Published assets, embedded documentation and actual
public-module retrieval are verified afterward. Native execution is Linux
amd64; other targets receive build/checksum verification. Local installation
is separate and is not part of this release request.

See the [release checkpoints](release-checkpoints.md).
