# NOE v2.0.0

NOE's managed agent runtime can now be embedded directly in a Go application.
Tasks and generated tools execute in fresh JavaScript runtimes in the host
process, without a separate NOE executable or internal HTTP RPC connection.
The CLI and the embedding APIs use the same execution and agent operations.

## Public Go APIs

- `stdlib.Profile` selects one environment, individual capabilities, a loader
  factory and an initializer. `Execute` and `NewRuntime` manage execution;
  `Attach` supports an application-owned VM and loop. `FileLoader` loads local
  modules through the selected filesystem with a fresh cache per execution.
- `agent.NewHost` and scoped Clients provide agent execution, queueing, retained
  results, steering, cancellation and shutdown. `agent.Attach` exposes a borrowed
  Host to JavaScript. Closing a Client cancels and joins its owned work while
  other Clients can continue using the Host.
- `agent/model` supplies catalog, generation, decision and image operations
  without a Host. `agent/auth` saves credentials at an explicit path, and
  `agent/log` analyzes caller-supplied JSONL data. Their bindings can be installed
  independently.

The module path is `forge.harakara.site/littleisland/noe/v2`. This is the first stable v2 module release. Checkout and isolated-artifact
consumer checks passed before publication; published-module verification is
recorded separately in the release checkpoints. Go 1.27.2 and go-quickjs v0.27.0 remain the supported versions.
Provider SDK dependencies are unchanged from v1.16.0.

## Breaking changes

- Go `stdlib.Install`/`Config` and `agent.Install`/`Config` are replaced by
  profiles, managed execution, a model service and a Host. Capabilities are
  selected independently. Library environment maps default to empty; callers
  provide environment, loaders, credential paths and instruction sources.
- Agent task/tool VMs share the application's OS process. `process.pid` no
  longer identifies a separate task process. End a task or instance through
  its scoped API rather than signaling a presumed child PID.
- JavaScript `interrupt_agent` is replaced by `cancel_task` for one accepted
  command and `stop_agent` for an instance and its queue. The human CLI
  `noe interrupt --run|--agent` remains available.
- Saved-file variants of `observe_agent` are removed. Live observation uses
  `observe_agent({agentId})`; saved logs are read by the caller and passed to
  `noe:agent-log.analyze_log`. CLI `noe observe` retains file/follow/wait behavior.
- Host runtime templates leave standard streams unset; the executor owns their
  bounded capture. Custom embedding stdio must implement supported cancellable
  I/O contracts. Optional POSIX command helpers are selected explicitly by the
  embedding application.

The CLI continues to supply NOE's credential/configuration locations,
instruction directories, OS environment, process helper, control discovery,
event files and bundled documentation. These application conventions are no
longer implicit library defaults. See the [v2 migration guide](../v2-migration.md)
and [Go embedding guides](../go-embedding.md).

## Validation

Validation includes unit/race/E2E suites, sustained Go Client waits and
cancellation, six-target compilation, independent module consumers, all 41
JavaScript example files, real OpenRouter/OpenCode Go/ChatGPT calls, and a small
Go daemon built by NOE using the public embedding APIs. Native execution was
checked on Linux amd64; other targets have compilation evidence. Long-term
continuous operation was not tested.

Release-specific preparation and later publication evidence are recorded in
the [release checkpoints](release-checkpoints.md).
