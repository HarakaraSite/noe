# NOE v2.29.0

Managed agent runs now reuse an OpenAI Responses WebSocket connection across
model/tool turns. Both built-in OpenAI providers, openai-chatgpt with OAuth
and openai-api with an API key, enable this transport by default.

## Continuation and lifetime

An unchanged conversation sends only new input items with the last completed
response ID. Trim, history/configuration replacement, reconnection, or a known
server-side continuation cache miss starts from current complete history.
Recovery preserves completed local tool work. Existing logical-request retry,
observations, usage reporting, and provider error categories remain in use.

Each managed run owns its connection. Completion, cancellation, operation
closure, and Host closure release it. Queued runs and parent/child runs have
separate connections. Borrowed model services and HTTP clients remain usable.

## Configuration and compatibility

Built-in OpenAI providers use transport=auto: managed OpenAI Responses calls
use WebSocket, while other API modes use HTTP/SSE. Set transport=sse in a
provider override to retain the previous managed path. Explicit websocket
requires sdk=openai and api=responses. Custom provider definitions default
to SSE; enabling WebSocket requires endpoint support for HTTP upgrades.

Injected Go clients support *http.Client, including custom RoundTrippers.
A bespoke Do-only client must expose WebSocketHTTPClient() *http.Client to
preserve its upgrade policy, or select SSE. Authentication and configured
endpoint/header policy remain associated with the selected provider; errors
do not automatically switch credentials or transports.

Public Go/JavaScript function signatures are unchanged. Standalone
model.Service.Generate() and independent noe:model calls retain HTTP/SSE.
A standalone persistent-session API remains a future note only. See the
[provider configuration](../providers.md#openai-responses-transport),
[Go embedding guide](../go-agent-embedding.md), and
[implementation record](../development/agentlib-openai-websocket-idea.md#managed-run-implementation--2026-11-18).

## Verification and distribution

Whole-tree unit/E2E, affected race checks, vet, managed GoHost/JavaScript
fixtures, and checkout/artifact Go consumers passed during implementation.
Final handshake error-classification changes received focused race/vet and
repeated external-consumer checks. Live functional checks completed one tool
execution and two model calls over one WebSocket for each authentication
route. Earlier synthetic transport measurements are recorded separately;
reduced upload size does not reduce logical input-token counts or guarantee
whole-run latency gains.

Dependencies remain unchanged, including go-quickjs v0.38.0 with JIT disabled.
Release verification reuses completed implementation checks and exercises
the native binary against a local transport fixture without paid requests.
CI builds six binaries and SHA256SUMS from the immutable tag. Publication
includes verified installation at both existing vm201 executable paths,
retaining previous copies. See the [release checkpoints](release-checkpoints.md).
