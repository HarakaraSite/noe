# NOE v1.7.0

Agents can now inspect local images and call an independent image-generation model through the new `noe:image` module.

## Images in agent tasks

- Call `read_image(path, {detail})` inside `run_js` to attach a local PNG, JPEG, or WebP file to the next model request. The host snapshots the image bytes; JavaScript and logs receive metadata only.
- Retain committed images across queued tasks in the same agent instance. Context trimming removes each assistant/tool/image exchange as one complete block and protects the latest block.
- Select attachments in `afterTool` with `event.images` and `{result, imageIds}`. Existing result replacement preserves images unless explicitly excluded.
- Account for images separately from text in context estimates, with an explicitly labelled approximation rather than Base64 length.

## Independent image generation

Call `generate_image({provider, model, prompt, output, parameters})` from ordinary JavaScript or `run_js`. The provider/model are explicit and independent of the parent agent. The API validates one returned image and atomically saves it; `read_image(result.path)` lets the parent inspect the result.

The initial built-in routes are OpenRouter's `openai/gpt-image-2.5-flare` and OpenAI API-key access to `gpt-image-2.5-flare`. ChatGPT sign-in and OpenCode Go image generation are unsupported. Provider defaults include a separate `imageGeneration` endpoint configuration, with the existing external JSON overrides. `list_models({kind:"image"})` returns configured image candidates.

`ImageError` preserves a stable classification and available provider reason/status/request ID. Image requests respect cancellation and shared provider-call limits. JSONL, `--observe`, and parent observation include read/generation metadata and tool attachment selections without image payloads.

## Other changes since v1.6.1

- Clarify computed context budgets and populate model-window metadata.
- Add an HTTP agent-server example with browser observation and controls.
- Organize examples by purpose, with local guides and supporting data.

## Validation and use

Live checks exercised API-key and ChatGPT Vision routes, independent generation, and parent generation followed by readback. In the four-color fixture, Sol identified every quadrant correctly; Luna made color/position errors even in a direct request. Transmitted image hashes matched the source. Model recognition quality remains separate from transport correctness.

See the [image guide](https://forge.harakara.site/littleisland/noe/src/tag/v1.7.0/docs/agent-images.md), [examples](https://forge.harakara.site/littleisland/noe/src/tag/v1.7.0/examples/image/README.md), [implementation checks](https://forge.harakara.site/littleisland/noe/src/tag/v1.7.0/docs/agent-images-implementation.md), [live results](https://forge.harakara.site/littleisland/noe/src/tag/v1.7.0/docs/agent-images-integration.md), and [release checks](https://forge.harakara.site/littleisland/noe/src/tag/v1.7.0/docs/release-checkpoints.md).

WebP decoding adds the pure-Go `golang.org/x/image v0.47.0` dependency. go-quickjs remains at v0.27.0. Image editing, masks, multiple generated images per request, URL image input, and Worker use are outside this release. Downloads cover Linux, macOS, and Windows on amd64 and arm64, with `SHA256SUMS`; native execution is checked on Linux amd64.
