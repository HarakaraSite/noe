# NOE v2.4.0

NOE reduces the text exchanged during agent work: API member lookups return
compact context, oversized tool results become explicit previews, and the
built-in openai-chatgpt provider accepts JavaScript source directly.
Go 1.27.2, upstream go-quickjs v0.28.0 and dependency versions are unchanged.

## Smaller model-facing results

After `afterTool`, the serialized result has a shared default text budget of
3 KiB (3,072 UTF-8 bytes), including stdout, stderr, data, diagnostics and
arbitrary hook replacements. Results within budget keep their existing shape.
Larger results use `outputPreview`, `outputLimit` and original execution status
in `execution`. The preview is incomplete JSON text, not a complete `data` value.
Byte counts and guidance make omissions visible so agents can narrow searches,
return filenames/counts, or read the relevant part.

The budget covers preview and diagnostic text. Fixed metadata and JSON
escaping are additional. Original captured results remain available to hooks
and execution events; the existing independent stdout/stderr capture limit
is unchanged. Images retain their dedicated path. Sources are not replayed,
and full artifacts are not saved automatically.

When the required content itself is larger, specify a per-call budget after
the operation comment:

```js
// Read the required HTTP detail.
// @noe: {"outputBytes": 12288}
import {docs} from "noe:docs";
console.log(docs("noe:http", "serve"));
```

Invalid or duplicate pragmas produce a setup diagnostic before execution.
Consumers of model-facing results and `tool.finished.result` must handle the
preview envelope. `tool.finished.rawResult` remains the captured runner result;
`hookResult` preserves a changed hook value when previewing would otherwise
lose it. Direct Go execution results are unaffected. See the
[execution guide](../execution-results.md) and [event guide](../events.md).

## Compact reference and raw JavaScript

`docs(topic, member)` now includes the topic name, short summary, type and
availability context, and selected detail. Full topic overviews and member
lists remain available. Relevant shared usage conditions are retained in the
details. The same seven globals lookups measured 38,368 characters before and
8,345 after, a 78.25% text reduction; this is not a task-wide token benchmark.

The built-in openai-chatgpt provider sends `run_js` as a Responses text custom
tool. Models supply the JavaScript module itself without JSON wrapping or code
fences. Hooks still receive normalized `{code}` arguments, while `rawArguments`
is the original source for this transport. Native reasoning and call/result
identity are preserved. Other providers default to JSON; `runJSInput: "json"`
selects the previous format explicitly. See [provider configuration](../providers.md).

## Cancellation and examples

Standalone `noe observe` now responds to cancellation while its output is
blocked. The examples add an Exa MCP client and a JSONL socket daemon, including
the flow for discovering and invoking MCP tools from JavaScript. See the
[examples](../../examples/README.md).

## Validation

Implementation passed full unit tests, affected runtime/provider tests,
output/hook/cancellation/docs/context E2E, vet, and normal/critical reviews.
Real openai-chatgpt tasks verified raw JavaScript continuation, narrowing a
search after overflow, and complete documentation retrieval with an explicit
budget. The first search probe also recorded and recovered from an API-shape
mistake; success and token usage are recorded without claiming a controlled
token-efficiency improvement.

Existing valid implementation results are reused for release preparation.
CI builds six distribution binaries and checksums without repeating source
tests. Native execution evidence is Linux amd64. See the
[implementation record](../development/token-efficiency-implementation.md) and
[release checkpoints](release-checkpoints.md).
