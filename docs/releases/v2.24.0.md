# NOE v2.24.0

This release corrects Headers/Response, Fetch body consumption, stream tee
lifecycle, cloned body byte ownership and multipart framing/serialization.
It includes `66c5703`, `efa3f82`, `48659fe`, `f280741` and `6ca7ec2`.
Runtime dependencies, host capabilities and the Go `/v2` module path are unchanged.

## Headers and Response

Headers validates ByteString inputs and HTTP names/values, keeps a private list,
observes mutations during iteration and preserves separate Set-Cookie entries.
Request/Response retain stable readonly Headers references. Native HTTP snapshots
preserve wire bytes and private state even when public getters are shadowed.

Response validates status, reason phrases and body usability. Metadata is readonly;
constructed responses have type default, empty url and false redirected.
Response.json, error and redirect use their documented standard contracts.
Error/redirect/fetched headers are immutable, including after clone. Native
HEAD/null-body responses release unused readers and expose null body. The existing
WebSocket upgrade helper retains its private status-101 construction path.

## Body consumption and cloning

Body helpers consume the current stream once. A reader lock alone does not set
bodyUsed; reads and cancellation do. Locked/disturbed bodies reject helpers and
cloning. Byte chunks and helper results are copied, invalid chunks reject and
producer errors retain their identity. Finite cloned/transferred uploads preserve
Content-Length and redirect replay. Fetch retains entry-time headers and observes
an abort before dispatch after buffering. Unusable server responses enter onError
before sending headers.

Both tee cancellations share the underlying cleanup result and ordered reasons.
Source errors discard unread buffered data while preserving reads already
accepted. Start both branch cancellations before awaiting them when stopping both.
Body clones isolate ordinary Uint8Array buffers before delivery, so editing or
transferring one branch cannot corrupt its sibling. SharedArrayBuffer remains
shared intentionally. Public tee keeps its existing chunk identity.

## Multipart data

Multipart parsing recognizes MIME delimiter lines rather than inline boundary-like
text. A field such as `before--fixtureafter` and binary file contents remain intact.
Preamble/epilogue, delimiter padding, chunk splits, part order and trailing file
line breaks are preserved. Outgoing text values normalize CR/LF to CRLF without
changing original FormData entries or file bytes; incoming text stays as received.

**Behavior compatibility:** callers must use public Headers/body APIs instead of
removed implementation properties. Supply valid header names/values, statuses
and byte chunks; initialize native Response metadata through the transport rather
than ResponseInit.url or property writes. Await both tee cancellations together.
These corrections intentionally change previously permissive or inconsistent
behavior. Types, embedded references, examples and main/Worker consumers agree.

## Scope and verification

Existing native backends, limits, grants and runtime/Worker cleanup remain shared.
Full BodyInit/BufferSource conversion, arbitrary-value cloneForBranch2, resizable
buffer metadata, BYOB/byte-stream controllers, field-name/filename escaping,
broader MIME parsing and browser header/CORS/cache policy remain outside this
release. Complete Web or Deno conformance is not claimed.

Implementation evidence includes affected-package tests, focused race, declaration
checks, native HTTP/Worker transfer, independent bounded reviews for the first
four slices, and Deno/Go MIME interoperability for multipart. Required review
findings were fixed and verified. Prepared MCP SDK and Exa fixtures passed without
real provider calls; unchanged checks are reused. Checkout and standalone module
consumers cover main and Workers.

Release verification is scoped to version/build metadata and affected native
contracts/examples. CI builds six Linux/macOS/Windows amd64/arm64 binaries and
SHA256SUMS from an immutable tag without repeating source suites. Publication
verification checks downloaded assets, native behavior and direct published Go
consumers. Other target binaries are not executed natively. Go 1.27.2, pinned
go-quickjs v0.32.0 / go-intl v0.8.0, CGO-disabled builds and disabled JIT remain.

Publication includes verified installation at both existing vm201 paths, with old
binaries retained. Other hosts, running services and noebot are excluded. See the
[release checkpoints](release-checkpoints.md),
[Headers/Response](../development/stdlib-headers-response.md),
[Body consumption](../development/stdlib-body-consumption.md),
[tee lifecycle](../development/stdlib-stream-tee.md),
[clone bytes](../development/stdlib-body-clone-bytes.md) and
[multipart](../development/stdlib-multipart.md) records.
