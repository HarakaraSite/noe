# NOE v1.3.0

NOE adds managed agent lifetimes, live observation and control, OpenCode Go and OpenAI providers, ChatGPT sign-in, a configurable model catalog, and structured decisions. The JavaScript runtime remains a standalone, CGO-free binary.

## Agent startup: breaking changes

`createAgent()` and `agent.run()` have been removed. Use `run_agent` to wait for completion, or `spawn_agent` to receive an agent ID immediately after acceptance. Root agents now require explicit `provider`, `model`, and `effort` settings. Answers are returned in `snapshot.lastResult.answer`; normal task failures are recorded in the snapshot rather than rejecting the Promise.

```js
import { run_agent } from "noe:agent";

const snapshot = await run_agent({
  provider: "opencode-go",
  model: "deepseek-v4.1-flash",
  effort: "auto",
}, "Read README.md and summarize it in three points.");

if (snapshot.lastResult?.state !== "completed") {
  throw new Error(snapshot.lastResult?.error || snapshot.reason || "Agent failed");
}
console.log(snapshot.lastResult.answer);
```

Children in model-generated `run_js` inherit omitted provider/model/effort/maxTokens settings. Each task has independent history and a run ID, with automatic cache/routing IDs. Reasoning fields and native Responses output items are preserved between model calls. Additional instructions can be supplied as a fixed `system` string, including text loaded from a file.

`spawn_agent(..., {keepAlive:true})` accepts subsequent tasks through `queue_agent`; each queued task gets fresh history. `observe_agent` returns live state or reads saved JSONL. `steer_agent` adds instructions to the active task, and `interrupt_agent` cancels one task or the entire instance. Waiting instances remain owned by NOE or their parent run; they are not independent daemons.

## Providers and credentials

- **OpenRouter:** existing Chat Completions agent support and the Decisions API, using the OpenRouter Go SDK.
- **OpenCode Go:** Chat Completions and model-specific Responses routes through the OpenRouter Go SDK. Requests carry `User-Agent: noe/<version>` and a stable `x-opencode-session` per task, with distinct parent/child IDs.
- **OpenAI:** the official OpenAI Go SDK, with Responses by default for Sol/Luna. Choose `openai-chatgpt` for ChatGPT sign-in or `openai-api` for API-key authentication. External compatible profiles can also use Chat Completions.

Built-in settings can be overridden in `~/.config/noe/config.json` or `NOE_CONFIG_FILE`. Configure endpoints, headers, authentication files, parameters, model-specific routes, and catalog metadata. `list_models` reads the merged catalog without a provider request; scripts can still specify models directly.

The external [ChatGPT sign-in helper](https://forge.harakara.site/littleisland/noe/raw/tag/v1.3.0/scripts/auth-chatgpt.js) is distributed as JavaScript. Copy or download it to `~/.config/noe/auth-chatgpt.js`, then run `noe run ~/.config/noe/auth-chatgpt.js`. Go verifies and stores credentials, and refreshes tokens when needed. The helper is separate from the binary assets.

## Observation, controls, and REPL

`noe run --observe task.js` displays agent progress with joined thinking fragments, English labels, first-line `run_js` comments, success/failure, and final answers. Messages and answers use color-free Markdown formatting, including aligned tables. Ordinary command/script stdout is hidden in this view.

`--events` on `run`, `eval`, and `repl` records JSONL to a file or stdout. Events include generated JavaScript source and available exception details for investigation. From another terminal, use `noe agents`, `noe steer`, `noe queue`, and `noe interrupt`. `noe observe --follow` renders a growing event log.

The REPL now uses the pinned qjs line-editing implementation, with NOE's modules and lifecycle integration. It supports dynamic imports, top-level await forms, history, completion, and multiline input.

## Structured decisions

`noe:decision` exposes `decide({provider, model, state, questions})` for one-shot OpenRouter Decisions requests, separate from the agent loop. It works from scripts or `run_js`, returns the full response JSON, and supports provider-native image parts in decision state. A model-routing example combines `list_models`, a Jev decision, and agent startup.

## Validation and scope

Fixture and CLI/PTY tests cover provider payloads and reasoning history, credential refresh, controls, child ownership, cancellation, observations, and diagnostics. Live validation records cover OpenRouter agents and the three decision models (`typesafe/jev-1.14`, `perplexity/pplx-decider-v1.2`, `cloudflare/clef`), OpenCode Go Chat/Responses, and ChatGPT-plan Sol/Luna tool loops. The OpenAI API-key route and fresh browser sign-in flow were checked with fixtures; the live ChatGPT tests used refreshed existing credentials.

Messages, the Anthropic SDK, agent image inputs, independent background daemons, and automatic context compaction are not implemented. Scripts and agents use the current user's OS privileges. See the [README](https://forge.harakara.site/littleisland/noe/src/tag/v1.3.0/README.md), [Japanese README](https://forge.harakara.site/littleisland/noe/src/tag/v1.3.0/README.ja.md), and [API guide](https://forge.harakara.site/littleisland/noe/src/tag/v1.3.0/docs/api.md) for setup and migration.

## Downloads

Six standalone binaries cover Linux, macOS, and Windows on amd64 and arm64, with `SHA256SUMS`. Linux amd64 is tested natively. Other targets are cross-compiled; native runtime behavior on those platforms remains unverified here.
