# NOE v2.5.0

NOE uses one output-budget setting for stream capture and model-facing results,
and adds reusable JavaScript helpers for listing, reading, writing and editing
files. Go 1.27.2, upstream go-quickjs v0.28.0 and dependencies are unchanged.

## One output-budget setting

The default `run_js` budget rises from the published v2.4.0 default of 3 KiB to
**64 KiB**. The complete model-facing result JSON, including omission metadata,
JSON escaping, diagnostics and arbitrary `afterTool` replacements, fits within
the selected budget. Results within budget keep their existing shape; overflow
returns the existing explicit preview envelope and original execution status.
`outputLimit.returnedBytes` now counts the entire encoded envelope, rather than
only preview and diagnostic text.

For necessary larger output, specify a per-call budget:

```js
// Read the required document.
// @noe: {"outputBytes": 131072}
import {readFile} from "node:fs/promises";
console.log(await readFile("README.md", "utf8"));
```

The setting also controls stdout and stderr capture, so increasing it works for
both console output and default-export data. Each stream retains its beginning
and end if truncated; the combined final JSON still fits the one selected
budget. Accepted values are integers from **1024 to 262144 bytes (1–256 KiB)**.
The minimum leaves room for omission metadata. Out-of-range, malformed,
unknown-field or duplicate pragmas fail before the source executes.

Hooks and execution logs retain the captured runner result before final
projection. Capture omissions and final-preview omissions remain separately
reported. Sources are not replayed and full output artifacts are not saved
automatically. Direct Go execution results and image delivery are unchanged.
See the [execution guide](../execution-results.md).

## Workspace file and search libraries

[`.noe/lib/files/files.js`](../../.noe/lib/files/files.js) exports:

- `ls(path?, options?)`: cwd children by default; tree/depth and pagination options.
- `read_file(path, options?)`: full UTF-8 text by default, or a line range with continuation.
- `write_file(path, text)`: create parent directories and write or overwrite text.
- `edit_file(path, oldText, newText, options?)`: replace only the exact target text;
  ambiguous or missing targets fail without writing. Explicit `all: true` replaces
  every non-overlapping match. Return values summarize the edit rather than echoing
  the whole file.

These are external repository libraries, imported from JavaScript, not new native
tools or implicit globals. They are available with a repository checkout; binary
downloads do not embed them. Workspace instructions recommend using the helpers.
See the [file helper guide](../../.noe/lib/files/files.md).

This release also includes the independent `grep()` search and repository-map
libraries added since v2.4.0. Search defaults to regular expressions, prefers rg,
and falls back to GNU-compatible grep. `ls()` is now the advertised entry point
for ordinary directory inspection; `repoMap()` remains available.

## Examples and documentation

The agent-server example adds an HTTP wrapper, history UI and task controls.
JSONL analysis examples report token use, cache hits and comparisons. Architecture
and feature-inventory documentation now describe the current in-process v2 design.
See the [examples](../../examples/README.md).

## Validation

Implementation passed the affected agent, executor, API-doc and runtime Go tests;
CLI output/hook/event and embedded-doc E2E; 34 file-helper filesystem checks; and
JavaScript lint. Tests cover the 256 KiB ceiling, actual encoded JSON size,
Unicode/escaping, expanded stream capture, exact edits and ambiguous-edit rejection.
No paid model calls were needed; model adoption of the new file helpers has not
yet been measured.

Release preparation reuses these results and checks the versioned native build.
CI builds six binaries and checksums without repeating source tests. Native
execution evidence is Linux amd64. See the [release checkpoints](release-checkpoints.md).
