# NOE v2.9.0

This release adds a portable, agent-led development workflow and five small
core cleanups. Public Go/JavaScript APIs, Go 1.27.2, go-quickjs v0.29.0,
go-intl v0.8.0 and selected dependencies are unchanged.

## Portable development workflow

The source repository includes a copyable workflow under
[.noe/lib/workflow](../../.noe/lib/workflow/README.md). Start it from the
actual target repository root with a settled requirements file:

~~~sh
noe run .noe/lib/workflow/run.js --requirements docs/requirements.md
~~~

One native parent owns planning, independent normal/critical plan reviews,
implementation workers, independent code review, validation, slice commits
and the safe final push. The launcher waits for the parent and preserves
native failure/cancellation as a nonzero process status.

- Implementation workers implement, run focused checks and repair related
  failures continuously. There is no approval pause before testing or
  after a repair.
- There are no mandatory Jev calls or model-based stage approvals. The
  parent judges actual changes, execution evidence and independent review.
- Evidence is reused rather than repeatedly repackaged for stage approval.
  A handoff alone is not a reason to rerun valid checks.
- Routine and difficult implementation/exploration default to
  openai-chatgpt gpt-6.1-terra/high. Parent/general/planning remain Sol/high,
  and reviews remain Sol/xhigh.
- The optional workflow config supports `roles` only. The experimental
  `decision` configuration from development snapshots was removed without
  compatibility support; delete that section from older copied configs.
  This does not remove or alter NOE's general `noe:decision` API.
- Existing worktree changes are protected. Workers do not commit/push or
  recursively launch workflows. The parent commits completed slices and
  performs one ordinary final push only after validation and safety checks.

The workflow and instruction templates are external source files, not
built-in binary policy. Copy the complete folder and preserve your own
configuration. Updating the executable does not install or overwrite these
files. See the [outer-agent guidance](../../.noe/lib/workflow/agent-instruction.md)
and [parent procedure](../../.noe/lib/workflow/workflow.md).

## Small core improvements

1. Shell command preparation normalizes the selected environment once;
   non-Windows map normalization no longer sorts unnecessarily. Map
   isolation, authorization timing, Windows collision semantics and final
   environment-block sorting are preserved.
2. Saved-log analysis avoids copying complete first-read lines and computes
   the execution-wide maximum sequence during state reconstruction. Long
   lines, incomplete tails, cancellation, cursor and event behavior remain.
3. Consecutive thinking fragments accumulate without repeatedly copying the
   full text prefix. Group boundaries, first-event metadata and projected
   output are preserved.
4. Cancelling selected/active tasks skips searching the pending queue.
   Queued cancellation, final-answer gates and publication ordering remain.
5. The unused module-loader entry field and assignment are removed; source
   cache precedence, including empty in-memory entry source, is unchanged.

A bounded R3 microbenchmark with 512 x 32-byte fragments measured:

| Path | ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| Previous concatenation | 831,439 | 4,612,100 | 2,047 |
| Local accumulation | 176,775 | 235,025 | 1,042 |

This demonstrates a local reduction in repeated-prefix-copying cost, not
an end-to-end NOE speedup. Removing the loader field is state cleanup, not
a claim that it formerly held a second allocation of the source bytes.

## Validation and distribution

The five core slices passed focused package/caller checks and independent
reviews, targeted cancellation race checks, coordinated `go test ./...`
and `go vet ./...`, formatting and diff checks. Windows command-environment
tests were cross-compiled and reviewed, not executed natively.

Workflow offline/configuration/termination checks, standalone copied-folder
usage, lint and type checks passed. A real one-slice label-helper task
completed implementation, focused tests, independent plan/code reviews,
a slice commit and push to an isolated local bare remote. It took
408,330 ms and recorded zero decision events. It is not a controlled
before/after performance comparison.

Release preparation reuses this valid evidence rather than repeating full
source suites. The unchanged lightweight CI builds six CGO-free binaries,
creates SHA256SUMS and publishes the immutable tag. Published checksums,
native smoke behavior and public Go-module retrieval are verified afterward.
Native execution here is Linux amd64; other targets receive build/hash
verification. Local installation and process restarts are separate.
