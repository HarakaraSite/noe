# NOE v2.5.1

This maintenance release clarifies internal responsibility boundaries and removes
release-number dependencies from CLI tests. Public Go, JavaScript and CLI APIs,
ownership rules, cancellation and event ordering remain unchanged. Go 1.27.2,
official go-quickjs v0.28.0 and the other dependencies are unchanged.

## Internal responsibility boundaries

- Agent task commands now use explicit lifecycle operations for queue registration,
  selection, start, cancellation, final-answer commit and retained outcome commit.
  The existing Host mutex, publication gates and close/join ordering are preserved.
- Runtime Profile settings and normalization, lower-level configuration, and
  execution-local module loading are separated from attach/cleanup. The loader
  shares the binding's lifetime gate; borrowed resources remain borrowed.
- Worker configuration inheritance and capability rebinding are separated from
  VM startup, evaluation and teardown. Message cloning and BroadcastChannel
  registration have their own modules. Worker notifications still share the
  data FIFO, and parentPort.close is still distinct from actual Worker completion.
- The private agent task loop delegates run_js schema/validation/execution and
  hook-wrapped tool processing to separate modules. Raw execution facts, hook
  projections, image ownership and history/checkpoint ordering are preserved.

The existing private task-tool export retains its function identity. A named
re-export issue in the pinned engine is avoided with an equivalent import plus
local export; no engine fork or dependency replacement is introduced.
See the [implementation and validation record](../development/responsibility-boundaries-refactor-implementation.md).

## Release-independent version tests

CLI tests no longer hardcode a real release number. Unit tests supply a test
version and check all version-command aliases. The E2E fixture injects a test
version through the build linker flags and checks exact stdout, successful exit
and empty stderr. Release artifact versions are verified separately.

## Repository helpers and documentation

The repository Exa helper now supports bounded highlights, links-only search and
selected-page text retrieval. Highlights search defaults to five results, with a
maximum of twenty; links-only mode supports up to fifty. getContents fetches one
selected URL and requests tag-free Markdown, up to 20,000 characters. These are
external checkout libraries, not new native tools or embedded binary APIs.
See the [Exa helper guide](../../.noe/lib/exa/exa.md).

Documentation separates completed features from future proposals, describes the
new responsibility boundaries, and records two upstream engine issues. A proposal
to return control to a parent agent waiting on children is recorded only; no
interruptible-wait API or behavior change is included.

## Validation

The refactoring plan passed independent normal and critical reviews, and each
implementation slice passed related tests and independent code review with no
outstanding P2-or-higher finding. Full local unit/E2E execution, race checks,
vet, JavaScript lint, formatting and six-target compilation were completed.
The one pre-existing version-expectation failure was then removed by the
release-independent test change; the affected CLI suite and full E2E suite passed.

Release preparation reuses that evidence for unchanged source. CI builds six
binaries and checksums without repeating source tests. Native execution evidence
is Linux amd64; other targets have compilation/build evidence.
See the [release checkpoints](release-checkpoints.md).
