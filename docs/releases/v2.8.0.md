# NOE v2.8.0

This feature release adds HTTP/HTTPS ESM URL imports to NOE's CLI, managed
agent executions, module Workers with local entries, and opt-in Go profiles.
The engine remains go-quickjs v0.29.0 with go-intl v0.8.0. Go 1.27.2, the
NOE-maintained standard library origin, and all selected dependencies are
unchanged.

## Import public ESM libraries

- Static imports, named/star re-exports, dynamic import, and exact bare
  import-map aliases can resolve to absolute HTTP/HTTPS URLs.
- Remote relative dependencies resolve against the module's final URL,
  including origin-relative and scheme-relative paths.
- URL paths do not need a .js or .mjs suffix. The standard loader accepts
  JavaScript MIME types and text/plain, including Content-Type parameters.
  It reads UTF-8 and removes a leading UTF-8 BOM.
- Redirects use the final URL as module ID and dependency base. Aliases,
  original URLs, direct final URLs, and cycles share the same canonical
  module namespace within one runtime. Query/fragment differences remain
  distinct according to the documented URL rules.
- Successfully loaded source and module state are retained only for that
  runtime. Separate run_js calls, Workers, and runtimes fetch independently.

The CLI enables URL imports by default. See the [URL import guide](../url-import.md)
and [public ESM examples](../../examples/url-import/README.md).

## Explicit Go-host opt-in

Go hosts select the new structured provider:

```go
profile := stdlib.Profile{
    Loader: stdlib.ModuleLoader(stdlib.LoaderOptions{
        HTTP: &stdlib.ModuleHTTPOptions{},
    }),
}
```

Profile.Loader carries both the runtime-local factory and capability metadata.
ModuleHTTPOptions provides a borrowed HTTP client, an Allow callback for
initial and redirected requests, and a response-body limit. Default settings
are a 30-second request timeout and 32 MiB of decoded response body.
Requests and body reads honor the execution context.

Existing Profile.NewLoader, LoaderFactory, and FileLoader remain supported.
FileLoader stays local-only; selecting JavaScript fetch does not enable URL
imports, and a URL loader does not implicitly grant filesystem or fetch access.
Selecting both Loader and NewLoader is a configuration error.

Agent Hosts automatically report enabled/disabled/unknown URL-import facts
from the snapshotted profile to parents and children, without exposing maps,
secret URLs, headers, or clients. Legacy function factories remain opaque and
report unknown rather than having their identity guessed. Custom providers
are responsible for their explicit metadata.

## Boundaries and trust

- There is no download cache across runtimes, persistent cache, lockfile,
  content-hash pinning, conditional GET, or automatic retry.
- This is not npm/package.json/node_modules discovery, CommonJS support,
  TypeScript/JSX transformation, or arbitrary Node/browser package compatibility.
- CLI and standard Worker entries remain local. Direct URLs and URL aliases
  are rejected before a Worker entry request; Worker dependencies may use URLs.
- Module fetching is synchronous and pauses jobs/timers in that runtime.
  Cancellation comes from the host execution context, Runtime.Cancel, task
  cancellation, or Worker shutdown, not a timer in the blocked JavaScript.
- Remote code executes with the selected profile's capabilities. The CLI
  keeps its existing user-OS-authority model; URL imports add no origin
  sandbox or code-safety guarantee. Use trusted sources.
- A versioned URL is not a content hash. Availability and contents can change
  at the provider, and dependency graphs are not atomically snapshotted.

## Validation and distribution

Four implementation slices each passed targeted tests and independent code
review after normal and critical plan re-reviews. The full unit/local-E2E
pass succeeded except for one obsolete documentation phrase assertion; that
test was updated to verify the new contract, its affected package passed,
and the correction was independently reviewed. Unchanged package results
were reused. Whole-tree vet, five affected-package race checks, external Go
consumer fixtures, formatting/lint, and documentation links passed.

The public lodash-es library was fetched from esm.sh and its chunk export
was used successfully through direct imports and alias/dynamic imports.
Ordinary tests use local fixtures, including parent-child agent imports,
independent run_js source acquisition, redirect/cycle identity, MIME/UTF-8,
selected capabilities, and cancellation during HTTP waits.

Release preparation reuses those implementation results rather than repeating
full suites. The unchanged lightweight CI builds all six distribution targets,
creates SHA256SUMS, and publishes the immutable tag. Downloaded assets and
published Go-module retrieval are checked after publication. Native execution
verification is Linux amd64; other targets receive build/checksum verification.
No paid model-provider call is needed.
