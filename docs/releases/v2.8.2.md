# NOE v2.8.2

This maintenance release fixes non-regular image inputs and removes unused
internal processing. Go 1.27.2, go-quickjs v0.29.0, go-intl v0.8.0, public
APIs and selected dependencies are unchanged.

## Image input

- Image reads check file type through the execution's selected filesystem.
  FIFOs, directories and other non-regular inputs are rejected with
  `ImageError` code `input` before reading their contents.
- The check is limited to image input. Generic filesystem APIs retain their
  existing behavior, including their ability to use special files.
- Regular images, symlinks to permitted regular files, read-only filesystem
  profiles, image snapshots and cancellation retain their existing behavior.
- This is a pre-read type check, not a guarantee against a different process
  replacing a path between inspection and opening. NOE remains not a sandbox.

## Internal cleanup

- Remove obsolete direct-OS image read/save adapters. Codec and output-safety
  tests now use the live decoding and model-binding/filesystem paths.
- Remove unused internal Node/path installation and process-group wrappers,
  retaining the live implementations and process-identity cleanup.
- Select explicit or inherited context configuration before normalizing it
  once per boundary. Absent, undefined, null, override and task-default
  semantics, including execution-limit validation, are preserved.
- Resolve Staticcheck findings through unused-code removal and equivalent
  simplifications. An intentional synchronization barrier in a wait test is
  preserved with a narrowly justified suppression.

The source-only unused-code and security-tool investigations do not add
runtime dependencies, blanket suppressions, or new CI gates. Broader
cross-module commonization and Markdown state cleanup are not included.

## Validation and distribution

The cleanup passed the full local unit suite and independent review.
The subsequent image-input fix passed affected-package and managed image
tests, regular-file/symlink/read-only/cancellation checks, and the FIFO
regression. Restoring the previous reader through a temporary Go overlay
caused that regression to fail by blocking, as expected. Development
Staticcheck, changed-JavaScript lint, formatting and diff checks passed.

Release preparation reuses this source evidence instead of repeating
unrelated full suites, race or long-duration checks. The unchanged
lightweight CI builds six CGO-free binaries, creates SHA256SUMS and
publishes the immutable tag. Published artifacts and public-module
retrieval are verified afterward. Local installation is not part of
this release request.

Native runtime verification is Linux amd64; other distribution targets
receive build/checksum verification, not native execution on this host.
See the [release checkpoints](release-checkpoints.md).
