# NOE v1.13.0

NOE now assembles its generic JavaScript APIs through one internal standard-library boundary. The CLI and Workers use the same composition of the maintained core library, NOE native I/O, bundled docs, and shared output writers. Existing JavaScript module names, exports, permissions, and HTTP behavior remain available.

## Standard-library composition

The new internal composition package separates generic API installation from CLI and agent execution policy. It preserves partial capability configuration, copies mutable settings before installation, and retains Worker constructors, loaders, limits, and installation callbacks. Worker stdin is not inherited, and terminating a Worker leaves its parent's shared output usable.

DNS configuration is copied and rebound to each Worker's own event loop, so asynchronous results do not depend on the parent's loop. Native I/O installation cleans up its Host on every error return after allocation. Output normalization preserves context-aware writes and borrowed destinations, including valid writers whose interface fields hold non-comparable values.

The [English Go embedding example](https://forge.harakara.site/littleisland/noe/src/tag/v1.13.0/examples/embedding/README.md) demonstrates a host that imports neither the CLI nor agent/provider packages. It runs inside this repository using internal Go packages; this release does **not** yet provide a public Go embedding library or change the module path to `/v2`.

## Stabilization before v2.0.0

v1.13.0 is intended for daily use and small bug fixes before deciding that NOE is ready for v2.0.0. The next-stage [public Go library plan](https://forge.harakara.site/littleisland/noe/src/tag/v1.13.0/docs/development/stdlib-step7-library-plan.md) has been reviewed, but remains unimplemented. It separates generic-library publication from later agent integration. A completed plan is not a claim that the library is published or that daily-use stabilization is complete.

## Validation and compatibility

The [implementation record](https://forge.harakara.site/littleisland/noe/src/tag/v1.13.0/docs/development/stdlib-step6-composition-implementation.md) covers partial hosts, real child-process environment and cwd behavior, nested Workers, callback failures, DNS ownership, output lifetimes, and independent code review. A writer-comparison finding was corrected and re-reviewed with no remaining P2-or-higher issues.

Release checks also exposed a timing assumption in two existing socket-cleanup tests: a resolved Promise can precede the native producer's final completion. The tests now join those producers with a bounded wait before checking that the runtime is idle. The idle and resource-ownership assertions remain in place; production socket behavior is unchanged.

Before release preparation, full unit, race, E2E, and vet checks passed, together with six-target builds and test compilation. The four-mode API inventory and primary CLI contracts matched the previous version. A basic real OpenCode Go / `deepseek-v4.1-flash` task completed after a retry that explicitly named `noe:http`; it consulted the bundled docs without being instructed to do so. The initial unsuccessful attempt and the successful retry are both retained in the verification record.

The engine remains go-quickjs v0.27.0, and dependency versions are unchanged. No new JavaScript option, API rename, or Node.js compatibility layer is introduced. Downloads cover Linux, macOS, and Windows on amd64 and arm64 with SHA256SUMS. Native execution is verified on Linux amd64; other targets have compilation evidence. Release-specific gates and published-asset verification are recorded in the [release checkpoints](https://forge.harakara.site/littleisland/noe/src/branch/main/docs/releases/release-checkpoints.md).
