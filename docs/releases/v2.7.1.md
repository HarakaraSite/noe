# NOE v2.7.1

This maintenance release updates the official go-quickjs engine from v0.28.0
to v0.29.0 and its go-intl dependency from v0.6.1 to v0.8.0. Go 1.27.2 and all
other selected dependency versions are unchanged. The public Go/JS API is
unchanged, but corrected JavaScript and internationalization behavior can
change script results.

## Module fixes

- Block-scoped function declarations inside ES modules are initialized again.
  An async function declared inside a try block can be called, and an inner
  function correctly shadows an outer function of the same name. This resolves
  [upstream issue #4](https://github.com/go-quickjs/go-quickjs/issues/4).
- Named re-exports correctly resolve module specifiers containing a colon,
  including `node:*` and `noe:*`. This resolves
  [upstream issue #5](https://github.com/go-quickjs/go-quickjs/issues/5).
- NOE's private task module now directly re-exports `executeToolWithHooks`
  from its pipeline module instead of relying on the import/local-export
  workaround. The import needed by the task loop remains; the exported
  function's identity is preserved.
- Upstream also corrects module global-object access: global getter/setter
  receivers and global-variable assignments use the actual global object.

## Intl, dates and other observable changes

The go-intl update and standards-mode corrections affect `Intl`, `Date`,
`Temporal` and related locale operations. Review scripts that compare formatted
output or resolved options against fixed strings. Confirmed examples include:

- A Telugu/Buddhist month-and-year formatter now reports `year: "numeric"`
  in `resolvedOptions()`, rather than omitting it.
- `getTimezoneOffset()` for Africa/Abidjan on 1900-01-01 now includes historical
  seconds: `16.133333333333333` instead of `16`.
- Locale fallback uses the runtime/host default locale consistently. Under a
  Korean default, `new Intl.Locale("ak").getCollations()` additionally includes
  `searchjl` and `unihan`.

Other upstream interpreter changes include generators/iterators, try/finally,
tail calls, property operations, strings, numbers, Math and regular expressions.
Some are specification corrections, not just performance changes. NOE-wide
performance improvements have not been measured.

## Preserved boundaries

- NOE's standard library remains its locally maintained snapshot derived from
  upstream v0.27.0. Its HTTP streaming, Worker ownership and other local changes
  are retained; the snapshot is not re-imported or relabeled as v0.29.0.
- JIT is not enabled. The engine update does not add the `quickjs_jit` build tag
  or the `WithJIT()` option to NOE.
- CGO is not required; the six distribution targets and release workflow are
  unchanged.
- The hook failure isolation and notification contract introduced in
  [v2.7.0](v2.7.0.md) is retained.

## Validation

The dependency candidate passed full unit and local E2E suites, public Go
consumer fixtures and all six target compilation checks. After restoring the
direct re-export and adding a NOE-level block-declaration regression test,
affected executor/runtime tests, CLI hook run/eval paths, four-package race
checks, related vet, lint, formatting and diff checks passed. Independent review
accepted the implementation; its documentation finding was corrected.

Release preparation reuses those results. The unchanged lightweight CI builds
six binaries, generates SHA256SUMS and publishes the immutable tag. Native
execution verification is Linux amd64; other targets receive compilation/build
and checksum verification, not native execution on this host. No paid model
provider call is required.
