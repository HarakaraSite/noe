# NOE v1.15.1

This patch preserves command failure details in synchronous JavaScript calls, isolates test agents from inherited connections, and improves the built-in `run_js` guidance.

## Synchronous command errors

`execFileSync` and `execSync` now throw JavaScript errors with `code`, `stdout`, and `stderr`, matching the useful failure details already available from asynchronous command execution. Agent tool responses and event logs retain those details when a synchronous command fails.

Successful calls still return strings. Existing command options, output capture limits, and runtime cancellation behavior are preserved. Failures before a process starts retain the existing `code: 0` convention; callers should use the thrown error to detect failure.

## Test agent isolation

CLI and E2E test suites now clear inherited `NOE_AGENT_CONNECTION` before running their fixtures. Running the tests from inside an agent no longer makes test agents connect to the outer agent. Managed child-process entry retains its connection, so real parent/child fixture tests continue to work. Production connection inheritance is unchanged.

## Practical run_js reference

Initial agent instructions and the bundled `noe:run_js` reference now include practical recipes for files, commands, imports, HTTP, agents, and error diagnosis. The reference clarifies directory metadata, supported imports, output capture, process access, and independent versus sequential operations. These changes improve guidance without changing the JavaScript API.

Dependencies and the pinned go-quickjs engine are unchanged. The executable remains on the v1 release line; this does not publish a v2 Go module. Validation evidence is recorded in [release checkpoints](release-checkpoints.md).
