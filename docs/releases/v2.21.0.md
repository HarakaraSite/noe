# NOE v2.21.0

This release adds practical User Timing and CustomEvent APIs and corrects the
existing UTF-8 codec and EventTarget listener contracts. It includes implementation
checkpoints `a5a52ed` and `2e7228f`. Runtime dependencies, host capabilities and the
Go `/v2` module path are unchanged.

## Encoding and decoding

- TextEncoder.encodeInto writes complete UTF-8 characters within the destination
  view and reports consumed UTF-16 code units and written bytes accurately.
- TextDecoder follows UTF-8 error boundaries, retains partial sequences across
  streaming calls, handles a BOM split across chunks, and preserves unconsumed
  input after fatal streaming errors. All six standard UTF-8 labels are accepted.
- Decoder metadata is readonly and branded. Inputs use exact buffer/view spans,
  fixed shared backing is supported, and detached decoder inputs are empty.
  Resizable/growable backing is rejected under the current Web IDL annotations.
  Additional encoding families remain unsupported.
- TextDecoderStream, Blob and other existing decoder users share the correction.

## User Timing and CustomEvent

performance.mark and measure return actual PerformanceMark/PerformanceMeasure
entries. Entry queries and clear methods operate on each runtime's independent
timeline. Supported overloads, readonly attributes, branded getters, constructor
restrictions and validation follow the documented User Timing slice. Detail is
structured-cloned on entry creation. A standalone PerformanceMark does not enter
the timeline. PerformanceObserver, resource/navigation timing and newer Timeline
id/navigationId fields remain outside the supported surface.

CustomEvent extends Event with reference-preserving detail, standard initialization
and legacy initCustomEvent outside dispatch. Event state is readonly and private;
dispatch maintains target/currentTarget/phase, cancellation and propagation flags.
CustomEvent and Performance objects/entries reject structured cloning with
DataCloneError. Existing legacy opaque Event cloning is retained.

## Event listeners

Listeners are identified by type, callback identity and capture. Duplicate
registration keeps the original options. Capture listeners run before non-capture
listeners at a single target, with separate phase snapshots. Removal during
dispatch takes effect; once listeners are removed before invocation, including
reentrant dispatch. Passive listeners cannot cancel events.

The signal option removes listeners through actual abort algorithms before the
signal's abort event. Synthetic abort events do not abort signals or remove bound
listeners. Already-aborted signals prevent registration. Manual/once removal
detaches abort cleanup, while dependent signals retain active algorithms until
cleanup. These semantics also serve messaging, Workers, EventSource, WebSocket
and Performance. No browser DOM tree is introduced.

**Behavior compatibility:** callers relying on duplicate event registrations,
ignored listener options, malformed UTF-8 replacement counts, writable codec /
event state, or empty Performance stubs must adapt. Pass supported BufferSources
and UTF-8 labels, remove listeners with the matching capture flag, and use each
method's standard return value and errors. Types, embedded reference pages,
examples and external Go consumers are aligned.

## Verification and distribution

Affected stdlib/profile/runtime/CLI tests, focused race, types, docs, lint/vet,
legacy installation without a Loop, actual CLI examples and checkout/standalone
module-artifact Go consumers pass. Main and Workers require no additional grant.
The parent reviewed the decoder; a bounded independent listener review found a
private-abort early-check defect, which was corrected and independently verified.
No complete DOM/Encoding/Performance conformance audit is claimed.

Primary specifications control the contracts. Deno 2.9.7 comparison agrees on
core codec/listener corrections but differs on capture ordering and synthetic
abort cleanup; those differences do not weaken NOE's primary assertions.

Release verification reuses unchanged implementation evidence. CI builds six
Linux/macOS/Windows amd64/arm64 assets and SHA256SUMS from the immutable tag without
repeating source suites. Native runtime verification is Linux amd64; other targets
receive build/checksum/metadata verification. Go 1.27.2, go-quickjs v0.32.0,
go-intl v0.8.0, CGO-disabled builds and disabled JIT remain selected.

The release includes verified installation at both existing vm201 executable
paths with previous binaries retained. Other hosts, running-service restarts and
noebot changes are excluded. See the [release checkpoints](release-checkpoints.md),
[Web API basics](../development/stdlib-web-basics.md),
[decoder/listener contract](../development/stdlib-decoder-events.md), and
[example](../../examples/web-basics/README.md).
