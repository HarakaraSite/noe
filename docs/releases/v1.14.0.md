# NOE v1.14.0

NOE now provides separate Go packages for embedding its standard library and managed-agent APIs into a caller-owned go-quickjs runtime. NOE itself uses these boundaries. Existing JavaScript modules, CLI commands, permissions, and HTTP behavior remain available.

## Go embedding

The generic `stdlib` package installs the maintained JavaScript library, NOE native I/O, and bundled docs with explicit configuration and resource ownership. An application can select capabilities without importing the CLI or agent/provider SDKs into its build closure. See the [standard-library embedding guide](https://forge.harakara.site/littleisland/noe/src/tag/v1.14.0/docs/go-embedding.md).

The separate `agent` package adds managed agents, decisions, images, optional credential saving, provider injection, and observation. It uses the same internal bridge as NOE's CLI and scoped child processes. The embedding host supplies its context, stdlib Loop, loaders, and an explicit path to a separate NOE executable; it is never implicitly re-executed as NOE. Tasks and `run_js` run in those separate processes with the host user's OS authority.

A binding owns one cancellable agent lifetime. Closing it joins Go requests and child processes while leaving the caller's runtime, Loop, clients, and original output sinks available. Finite hosts capture the root Promise's success and failure, drive `Loop.RunUntil`, then close the binding. English [agent documentation](https://forge.harakara.site/littleisland/noe/src/tag/v1.14.0/docs/go-agent-embedding.md) and a [working Go example](https://forge.harakara.site/littleisland/noe/src/tag/v1.14.0/examples/agent-embedding/README.md) explain these contracts.

## v1 binaries and the Go module path

This is a **v1 CLI release**, not the v2.0.0 library publication. The source module now uses `forge.harakara.site/littleisland/noe/v2`, with public `/stdlib` and `/agent` packages. A v1.14.0 tag is not a valid v2 Go module version. Use a source checkout and the documented local replacement for embedding until a v2 tag is published. The `/v2` source path does not imply that a v2 release exists.

Steps 7.1 and 7.2 are implemented and verified. Daily use and small bug fixes will determine when to publish v2.0.0; this release does not claim that stabilization is finished.

## Validation and compatibility

The [standard-library record](https://forge.harakara.site/littleisland/noe/src/tag/v1.14.0/docs/development/stdlib-step7-library-implementation.md) and [agent record](https://forge.harakara.site/littleisland/noe/src/tag/v1.14.0/docs/development/stdlib-step72-agent-implementation.md) contain implementation, tests, and independent review. The agent review corrected a live-test completion check and finished with no remaining P0–P3 findings.

Full unit, race, E2E, and vet checks passed. Separate Go consumers passed both local-replacement and no-replacement synthetic-proxy tests, including independent module caches and six-target compilation. Main, Node-style Worker, nested Worker, and Web Worker API inventories match the preceding baseline. HTTP upload/receive streaming, cancellation, output ownership, hooks, and authentication fixtures also passed.

An external Go consumer completed a real OpenCode Go / `deepseek-v4.1-flash` task using three model requests and two `run_js` calls. It aggregated three records to 31, saved and reread the report, and returned a final answer.

The engine remains go-quickjs v0.27.0, and dependency versions are unchanged. Downloads cover Linux, macOS, and Windows on amd64 and arm64 with SHA256SUMS. Native execution is verified on Linux amd64; other targets have compilation evidence. Release gates and published-asset verification are recorded in the [release checkpoints](https://forge.harakara.site/littleisland/noe/src/branch/main/docs/releases/release-checkpoints.md).
