# NOE v2.27.0

This release updates go-quickjs from v0.37.1 to v0.38.0 and corrects the
Windows line-ending value exposed by NOE's OS module.

## Engine update

The engine incorporates upstream compiler and parser fixes for captured block
bindings on loop exits, nested `finally` execution and completion values,
computed object-rest keys, optional-chain deletion, loop labels, labelled-block
breaks, and async functions after line breaks. It also includes interpreter
improvements for object spread, sparse arrays, string concatenation and
`instanceof`; NOE-specific performance gains were not measured.

JIT remains disabled. Go remains 1.27.2, go-intl remains v0.9.0, and the public
Go and JavaScript API signatures are unchanged. NOE continues to use its own
standard library and module loader. See the
[integration record](../development/go-quickjs-v0.38.0-upgrade.md).

## Windows OS line endings

`os.EOL` and `node:os.EOL` now return `"\r\n"` on Windows and `"\n"` elsewhere,
through both named and default exports. Previously they returned LF on every
platform. Windows callers requiring LF for a file format should use an explicit
`"\n"`. This does not automatically normalize file or stream output.

The embedded API reference and TypeScript descriptions document the behavior.

## OpenAI Fast-mode documentation

The [OpenAI guide](../openai.md#fast-mode) documents requesting Fast with the
existing provider configuration: `priority` for the tested ChatGPT plan-sharing
route, and `fast` or `priority` for API-key access according to OpenAI's API
documentation. No new agent option or provider implementation is added.

The [investigation](../development/openai-fast-mode.md) records the earlier
v2.26.1 real-provider comparison and installed-agent check. A ChatGPT response
reporting `default` alone does not establish that Fast was ignored. Its measured
speed difference is a small-sample observation, not a universal speed or billing
guarantee.

## Verification

Eight compiler/parser regression cases fail against v0.37.1 and pass against
v0.38.0 in main, Workers, and repeatedly executed node:vm Scripts, matching Node.
Whole-tree unit/E2E, focused race, vet, module verification, independent stdlib
and agent consumers, and all six distribution-target compilation checks pass.
Windows and macOS are compile-only verification; Linux amd64 was run natively.

Release preparation reuses this completed implementation evidence. CI builds
the six distribution binaries and SHA256SUMS from the immutable tag without
repeating source suites. Publication includes verified installation at both
existing vm201 executable paths, retaining the previous binaries. See the
[release checkpoints](release-checkpoints.md).
