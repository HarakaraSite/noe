# Migrating from v2.15.0 to v2.16.0

This guide covers the standard-library API and behavior changes since
[v2.15.0](v2.15.0.md). The [v2.16.0 release notes](v2.16.0.md) cover the
release as a whole. EventSource and asynchronous SQLite are additions; using
them is optional and requires no migration to existing code.

## Changes at a glance

| Before | In v2.16.0 |
| --- | --- |
| `node:fs`, `node:fs/promises`, `fs`, `fs/promises` | Import from `noe:fs`; asynchronous methods are direct named exports. |
| Node-style FileHandle overloads and result objects | Use options-based `open`, `read`/`readAt` returning bytes, and `write`/`writeAt` returning a byte count. |
| `node:process`, `process`, `node:child_process`, `child_process` imports | Use the independently selected exports from `noe:process`; metadata is the named `process` export. The global `process` remains when ProcessInfo is selected. |
| `node:http`, `http`, or global `serve`/`upgradeWebSocket` | Import host helpers from `noe:http`; standard `fetch` remains global. |
| `new WebSocket(url, protocols, {headers})` | Use `createWebSocket(url, {protocols, headers})` from `noe:http`. |
| WebSocket binary messages defaulting to `ArrayBuffer` | The default is `Blob`; set `binaryType = "arraybuffer"` when needed. |
| Synchronous `server.close()` | Await its `Promise<void>` or use `await using`. |
| Fetch/Serve body limits returning a successful truncated body | Reading past the limit now reports overflow; Serve's negative limit now means unlimited. |
| WebSocket close event reflecting the local request | Closing waits for the peer exchange and reports the peer's result. |

The removed modules and globals have no compatibility adapters. Bare `fs`,
`process`, `child_process`, and `http` names may be assigned through an import
map; the `node:` and `noe:` prefixes remain reserved.

## Filesystem

Import filesystem APIs from one module. Promise-based functions are direct
exports (`readFile`, `stat`, and so on); synchronous variants keep an explicit
`Sync` suffix. There is no `promises` property or `node:fs/promises` module.
`watch` is an async iterator, not an EventEmitter watcher.

```js
import {open} from "noe:fs";

{
  await using file = await open("migration-example.bin", {flags: "w+"});
  await file.write("hello");
  const bytes = await file.readAt(0, 5);
  console.log(new TextDecoder().decode(bytes));
}
```

`open(path, options?)` takes `{flags, mode}` rather than positional flags and
mode. `read(length?)` reads at the current cursor; `readAt(position, length)`
does not move it. Both return a `Uint8Array`, not `{bytesRead, buffer}`.
`write(data)` and `writeAt(position, data)` accept a string or byte view and
return the number of bytes written. `writeAt` does not move the cursor on a
non-append handle; append handles write at EOF. For a former buffer/offset/
length call, pass the selected typed-array range, such as
`data.subarray(offset, offset + length)`. Negative `truncate` lengths now
reject; use `truncate(0)` to clear a file.

Replace callback/EventEmitter `watch` usage with `for await (const event of
watch(path))`, or call `next()` and close the iterator. Breaking from a
`for await` loop closes observation; `await using` also disposes it.

## Processes and standard I/O

Import commands and metadata from `noe:process`:

```js
import api, {process, execFile} from "noe:process";

const {stdout: branch} = await execFile("git", ["branch", "--show-current"]);
console.log(api.process === process, process === globalThis.process, branch.trim());
```

The default export is a namespace containing the selected named exports.
Process metadata is at `api.process`, not `api.env` or `api.cwd`; command
helpers do not become properties of global `process`. `import {process}` is
the module form of the same object as global `process`.

The `Commands`, `ProcessInfo`, and `Stdio` host capabilities remain independently
selected. The module is present when any one is selected, but it exports only
the names enabled by the selected capabilities: command functions, the
`process` object, and/or `stdin`/`stdout`/`stderr`. For example, importing a
command does not also select process metadata or standard I/O. The global
`process` remains available when ProcessInfo is selected.

Standard I/O remains byte Web Streams. Replace an old stream import with
`noe:process` and use its Web Stream writer:

```js
import {stdout} from "noe:process";

const writer = stdout.getWriter();
try {
  await writer.write(new TextEncoder().encode("hello\n"));
} finally {
  writer.releaseLock();
}
```

## HTTP helpers and Serve lifecycle

`noe:http` contains host helpers only. It has no default export or `fetch`
export; use global `fetch`, `Request`, `Response`, and `Headers`. The module is
present when Serve or WebSockets is selected; Fetch alone does not install it.
Import `serve`, `createWebSocket`, and `upgradeWebSocket` by name. The listener
capability selects `serve`; WebSockets selects `createWebSocket`; the upgrade
helper requires both. Fetch selection is independent. The old `node:http` and
bare `http` imports and global `serve`/`upgradeWebSocket` helpers are removed.

`server.close()` now returns one shared `Promise<void>` that resolves after
graceful cleanup. It immediately stops new handler admission, lets active HTTP
work finish, and forces remaining HTTP connections after up to five seconds.
Use `await server.close()` when completion matters, or scope the listener:

```js
import {serve} from "noe:http";

{
  await using server = serve({port: 0}, request =>
    Response.json({url: request.url}));
  console.log(server.url);
}
```

Disposal waits on both normal and exceptional scope exit. A handler may start
`server.close()` and return its response, but must not await that close promise
inside its own handler; await it outside after the response completes. Closing
the HTTP server does not close upgraded WebSockets.

## Fetch and Serve body limits

Fetch response collectors and streams no longer turn a prefix at the configured
limit into a successful complete body. Reading through the boundary checks
actual EOF; an exact-limit body succeeds, and excess bytes cause a body error.
The check uses actual bytes, not `Content-Length`, and probes at most one extra
byte. A read at the exact boundary may wait for EOF, excess input, cancellation,
or timeout. A streaming reader may already have received the allowed prefix
before a later read fails; convenience collectors such as `text()` and `json()`
reject the collection instead of returning it as complete.

Serve request bodies now report excess input as a `RangeError` with
`code: "ERR_HTTP_BODY_TOO_LARGE"`. An uncaught overflow before response
headers are sent produces 413 by default; `onError` can choose a response.
Overflow after response streaming begins fails that transfer. As with Fetch,
incremental reads can yield the permitted prefix before the boundary check
reports the excess.

For Go Serve configuration, `MaxBodyBytes: 0` still selects the 32 MiB
default, a positive value is the finite cap, and a negative value now means
unlimited input (it previously behaved as an empty body). Fetch's zero value
also retains its 32 MiB default; negative Fetch limits were already unlimited.
The Serve limit is a host setting, not a JavaScript `serve()` option.

## WebSockets

The standard `WebSocket` constructor now has the standard two-argument surface.
For custom handshake headers, replace the v2.15.0 third-argument extension with
the synchronous host factory:

```js
import {createWebSocket} from "noe:http";

const socket = createWebSocket("wss://example.com/feed", {
  protocols: ["chat.v1"],
  headers: {Authorization: "Bearer <token>"},
});
socket.addEventListener("open", () => socket.send("hello"));
```

The factory returns the same WebSocket class in `CONNECTING`; listen for
`open` before sending. Without custom headers, use the global
`new WebSocket(url, protocols?)`. Binary messages now arrive as `Blob` by
default. Set `socket.binaryType = "arraybuffer"` before receiving if existing
code expects `ArrayBuffer`. Sending a `Blob` or `File` now sends binary bytes,
not text-coerced content.

Close validation now follows the standard constraints: a supplied code must
be 1000 or 3000–4999 after unsigned-short conversion, and the reason is at
most 123 UTF-8 bytes. Invalid arguments throw before changing socket state.
Closing while `CONNECTING` cancels the opening attempt and emits an error
before an unclean close event with code 1006. Handle those events instead of
waiting for a handshake.

For an established socket, `close()` sends an empty close frame. Use
`close(1000)` to send an explicit normal status; a reason without a code uses
1000. Closing allows up to five seconds for queued accepted sends and the
peer's close frame. `close()` itself still returns `void`; wait for the
`close` event when completion matters. Its `code` and `reason` describe the
peer: an empty peer frame reports 1005, and no peer close (for example, timeout
or abrupt EOF) reports 1006 with an empty reason. `wasClean` is true only when
both close frames complete successfully. Simultaneous close events can report
different peer results at each end.

## Configuration and ownership

These API changes reuse NOE's existing shared backends and host ownership; no
Go configuration fields or duplicate native backends are added.
They do not add filesystem grants, command authorization, network permission,
or WebSocket access by importing a module. Go hosts continue to select the
same capabilities independently: FS keeps `Root`, `Cwd`, and `ReadOnly`;
Commands, ProcessInfo, and Stdio remain separate; and Fetch, Serve, and
WebSockets remain separately selectable. Native handles, children, listeners,
and sockets retain runtime/Worker cleanup. Standard I/O streams continue to
borrow the configured host readers and writers.
