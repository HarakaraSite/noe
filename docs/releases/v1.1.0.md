# NOE v1.1.0

NOE now uses the full standard library provided by go-quickjs v0.25.3. Scripts can use filesystem and process modules, timers, Fetch and Web Streams, HTTP servers, WebSocket, command execution, DNS, crypto, and Workers.

## API migration

The `noe` JavaScript global and all `noe.*` APIs have been removed. Existing scripts need to migrate to the stdlib APIs:

- Use `process.argv.slice(2)`, `process.env`, `process.cwd()`, and `process.exit()` for the execution environment.
- Import file operations from `fs/promises` and asynchronous sleep from `timers/promises`.
- Use global `fetch()` and `serve()`. Fetch bodies are consumed once; server handlers receive a Web `Request` and return a `Response`.
- Use `process.stdin.read()` for standard input. This reads synchronously once and then returns `null`.

The [migration table](https://forge.harakara.site/littleisland/noe/src/tag/v1.1.0/docs/api.md#旧apiからの移行) includes all former APIs and their replacements. Examples and guides have been updated. The stdlib provides partial Web and Node-style APIs; npm, full Node.js/Deno compatibility, and the original QuickJS `std` module are not included.

## CLI and REPL

The `run`, `eval`, and `repl` commands, execution timeouts, and REPL history, completion, multiline input, and previous-result `_` remain available.

Interrupting timers in the REPL cancels them and allows the session to continue. If stdlib I/O, workers, or messaging resources remain active when an input fails or is interrupted, NOE closes the runtime and ends the session. See the [REPL guide](https://forge.harakara.site/littleisland/noe/src/tag/v1.1.0/docs/repl.md) for details.

## Downloads

Standalone binaries are provided for Linux, macOS, and Windows on amd64 and arm64. `SHA256SUMS` contains their checksums. No C runtime integration or separate JavaScript engine installation is required.
