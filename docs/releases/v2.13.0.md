# NOE v2.13.0

This release unifies the filesystem APIs, expands open-file and directory
operations, and reduces agent-library serialization and streaming overhead.
Go 1.27.2, go-quickjs v0.32.0, go-intl v0.8.0, and disabled JIT are unchanged.
The public Go packages retain their `/v2` import paths. This release includes
the breaking JavaScript filesystem changes described below.

## Filesystem API and migration

`node:fs/promises.open` is the canonical asynchronous handle entry point.
`fs/promises` and the `promises` objects on `node:fs`/`fs` expose the same
`open` function. The former `noe:fs-handle` module and docs topic are removed
without a compatibility adapter.

| Before | v2.13.0 |
| --- | --- |
| Import `open` from `noe:fs-handle` | Import from `node:fs/promises`. |
| `open(path, {mode: "r+"})` | `open(path, "r+")`. |
| `file.readAt(position, length)` returning `{data, bytesRead, eof}` | `file.read(buffer, {position, length})` returning `{bytesRead, buffer}`. There is no `eof` field. |
| `file.writeAt(position, bytes)` returning a number | `file.write(bytes, {position})` returning `{bytesWritten, buffer}`. |
| Numeric filesystem `error.code` | A symbolic string such as `ENOENT`, `EEXIST`, or `EBADF`; the native OS number is in `errno` when available. |
| String `info.mtime` | A Date. Use `toISOString()` for text or `mtimeMs` for epoch milliseconds. |
| Permission-only `info.mode` | POSIX file-type, permission, and special bits. Extract permissions with `mode & 0o777`. |

The numeric errno is the original platform OS value, rather than a promised
libuv-compatible number. Custom `ERR_INVALID_ARG`, `ERR_READ_ONLY`,
`ERR_FILE_CLOSED`, and fallback `ERR_IO` codes remain. FileHandle partial
failures retain their byte counts and original buffers. Native errors preserve
their Go causes for embedding hosts; caller-thrown JS exceptions retain their
identity. The common representation applies to synchronous, Promise, handle,
and file Web Stream operations.

```js
import {open} from "node:fs/promises";

const file = await open("data.bin", "r+");
try {
  const buffer = new Uint8Array(16);
  const {bytesRead} = await file.read(buffer, {position: 32});
  await file.write(buffer.subarray(0, bytesRead), {position: 32});
  await file.sync();
} finally {
  await file.close();
}
```

Omitted/null positions use the file cursor. Explicit safe-integer positions
leave it unchanged. Normal close rejects subsequent I/O and drains admitted
operations; execution shutdown force-closes owned resources without waiting
for JS callbacks. Open handles alone do not keep an evaluation alive.

Supported flags now include `r`, `r+`, `w`, `wx`, `w+`, `wx+`, `a`, `ax`,
`a+`, and `ax+`. Creation permissions default to `0o666`, subject to umask,
and explicit modes range from `0` to `0o777`. Append handles write at EOF
regardless of an explicit position. Exclusive creation preserves the final
directory entry, including dangling symlinks, and follows Root/ReadOnly policy.

FileHandles add descriptor-based `stat()`, `truncate(length = 0)`, and `sync()`.
Directory listings still return names by default; `{withFileTypes: true}`
selects `node:fs.Dirent` objects with names, parent paths, and type predicates.
Stat results are a supported subset of Node Stats, without BigInt metadata
or additional timestamp fields. Date/JSON timestamps have millisecond
precision, while `mtimeMs` may retain fractional milliseconds.

See the [phase 1](../development/stdlib-fs-integration.md) and
[phase 2](../development/stdlib-fs-basics.md) implementation records and the
[stdlib roadmap](../development/stdlib-roadmap.md).

## Agent library optimization

Context measurement and digests use streaming JSON output for ordinary
histories, avoiding complete temporary byte slices. Large individual values
retain buffering based on measured allocation behavior. Managed conversation
updates send revision-checked appends instead of repeatedly transferring the
entire history; restore and trim retain their snapshot contracts.

Chat and Responses SSE data are assembled incrementally instead of retaining
and replaying all raw events. OpenAI/OpenRouter SDKs continue driving their
usual streams. Public agent APIs, validation, ownership, cancellation, usage,
and completion gates retain their existing contracts.

Measurements and their limits are recorded in the
[context serialization](../development/agentlib-optimization.md) and
[conversation/SSE](../development/agentlib-checkpoint-sse-optimization.md)
notes. These local microbenchmarks do not establish provider or application
latency improvements.

## Verification and distribution

Passing implementation evidence is reused: affected unit/integration and
race checks, CLI execution modes and agent tools, external Go consumers,
TypeScript declarations, JS lint, vet, and independent filesystem reviews.
The finalized filesystem source passed six-target consumer builds, all six
offline library suites, and 170 tests from the remote noebot snapshot without
consumer changes. Agent optimization has its own unit/race/E2E evidence.

Release verification is limited to source/dependency evidence, a clean
release-flags build, version and focused native smoke checks. CI builds six
CGO-free binaries and publishes checksums. Published assets, embedded build
metadata, native behavior, and actual external Go consumers are checked
before local placement. Existing processes adopt the executable on their
next normal restart.
