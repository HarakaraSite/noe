# NOE v1.4.0

This release adds managed child processes, streaming standard I/O, and local import maps. Scripts, Workers, and autonomous agents can reuse prepared JavaScript libraries and communicate with long-running commands through live byte streams.

## Managed processes and streams

- Import `spawn` from `noe:process` to start a command with piped, inherited, or ignored stdin/stdout/stderr. Handles expose the command's PID, byte streams, `exited`, `kill()`, and `close()`.
- Import host `stdin`, `stdout`, `stderr`, and cancellation-aware `pipe()` from `noe:io`. Importing stdin does not start reading; stream operations do not close the borrowed host descriptors.
- Use both modules from ordinary scripts, Workers, and agent-generated `run_js`. The spawning runtime owns its children and reclaims them on cancellation or termination. This is not detached process execution.
- Keep the pinned standard library's existing `node:child_process`, `process.std*`, and Web Streams APIs unchanged.

See the [process and I/O guide](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/docs/process-io.md).

## Local ESM and import maps

- Add `--import-map path` to `run`, `eval`, and `repl`. Exact bare names map to local `.js` or `.mjs` modules, with relative targets resolved from the map file's directory.
- Support relative and absolute local paths and local `file:` URLs through a common resolver. Canonical paths share a module namespace and avoid repeated evaluation within a runtime.
- Fix the mapping at startup and inherit it through Workers, agent tasks, each `run_js`, and child agents. Changes to the original map do not change the active mapping.
- Retain successfully read library sources within each runtime. Fresh runtimes read files independently. Worker entry files still use the standard library's separate entry loader and are outside this retention guarantee.
- Preserve built-in module names and existing CLI argument boundaries. HTTP imports, npm/package discovery, prefix maps, and `scopes` are outside this initial exact-name subset.

Try the [included example](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/examples/import-map/main.js):

```sh
./noe run --import-map examples/import-map/import-map.json examples/import-map/main.js
# 6
```

See the [import map guide](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/docs/import-map.md).

## Reusable MCP SDK example

The [MCP example](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/scripts/spikes/process-io-mcp/README.md) separates the official SDK's `Client` export from an ordinary JavaScript process transport. It verifies main, Worker, and fixture-agent execution, concurrent response IDs, large UTF-8 messages, failure reporting, and child cleanup. Node/npm/esbuild are used only to prepare the bundle; no MCP-specific Go API or SDK core patch is required.

## Validation and downloads

The changes passed per-slice code reviews and an overall review. Release preparation checks cover unit tests, E2E tests including Linux PTY interactions, vet, race detection, and all six distribution builds. MCP acceptance uses a prepared SDK bundle and local fixtures; no real model-provider request is needed. Dependency versions are unchanged from v1.3.3.

Standalone binaries cover Linux, macOS, and Windows on amd64 and arm64, with `SHA256SUMS`. Linux amd64 is tested natively; the other targets are cross-compiled. See the [release checkpoints](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/docs/releases/release-checkpoints.md), [README](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/README.md), and [Japanese README](https://forge.harakara.site/littleisland/noe/src/tag/v1.4.0/README.ja.md).
