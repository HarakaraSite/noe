# NOE v2.2.0

NOE makes generated JavaScript follow ordinary ES-module rules and separates
returned data, captured output, execution status and diagnostics. This release
contains breaking changes to run_js and custom Go engine bindings. Go 1.27.2
remains required, and experimental JIT remains disabled.

## Breaking changes and migration

Agent helpers are no longer injected into run_js. Import every API explicitly:

```js
import {list_models} from "noe:agent";
export default await list_models();
```

Return JSON data with `export default value` or `export default await operation()`.
A final expression is not returned. An exported Promise, BigInt, function,
undefined or cyclic result fails with `JS_RESULT` in the serialize phase.
Execution may already have produced side effects; do not repeat such operations
automatically. Omitting a default export still succeeds without returned data.

Failures carry structured `diagnostics` and `phase`. stdout/stderr contain only
captured output. User exception code/signal/stdout/stderr are retained separately
under `diagnostics[].exception`; code is the NOE classification. Source positions
and frames are engine facts, including unhandled Promise and timer failures.

Custom Go bindings using engine types must switch imports from
`github.com/go-quickjs/go-quickjs` to
`forge.harakara.site/littleisland/noe/third_party/go-quickjs` (the alias `quickjs`
can remain). The managed engine is an independent module, version
`v0.28.1-noe.1`, derived from upstream v0.28.0. Its submodule tag is
`third_party/go-quickjs/v0.28.1-noe.1`. Types from the old and new module paths
are distinct. Published consumers do not need checkout-only replace directives.
Upstream source and licensing are retained; this is not an upstream GitHub release.

## Inspection and API discovery

`check(code)` from `noe:runtime`, and Go's `stdlib.Check`, compile and link a fresh
static module graph without evaluating module bodies. Results identify the
reached stage and structured failures. Dynamic imports and runtime behavior are
not certified. Custom Go inspection initializers and loaders can perform host
work. Only explicit `Profile.InspectInitialize` is used; it must own its resources
and leave the running execution's operation alive.

`describe(topic?, member?)` from `noe:docs` reports the documentation catalog,
actual exports, availability and explicitly documented signatures. Missing
reference text does not mean an API is unavailable. `docs` remains the detailed
human-readable reference. Export discovery does not evaluate module bodies.

## Complete tool results and processing

Large original tool results are retained in task-owned temporary artifacts.
Inline stdout/stderr keep their first and last 32 KiB; large data is omitted
with its size and resultRef. Oversized diagnostic previews preserve classification
and position while retaining the full original. `read_tool_result` from
`noe:agent` reads UTF-8 byte ranges of the original result JSON. The default page
is 24 KiB. References are available only within the same active task and expire
at task completion; persist needed results to ordinary files before returning.

Captured streams spill to disk, and cleanup joins owned work before removing
artifacts. Unchanged arguments and results cross the JS-to-Go reporting boundary
once. Hooks retain separate original and effective views, while provider-native
assistant history and queue session continuity are preserved.

## Additional changes

The agent-console example provides a resident agent's Queue, Steer, Interrupt
and stop controls, bounded browser paging, persisted history and full answers.
It is a loopback-only example, not a multi-user hosted service.

Explicit upstream `cyber_policy` errors are classified as policy failures and
are not retried automatically. Provider details are retained and unexecuted tool
calls are not run. Ordinary answer text is not guessed to be a policy error.

## Validation

The implementation passed per-slice code reviews, the full unit/E2E suite,
engine tests, race, vet, sustained waits and cancellation, six-target compilation,
and external stdlib/agent consumers. All 51 example JS/MJS files were reached
through their appropriate consumers; OAuth and the full task-loop workflow
also succeeded with real providers. A live model discovered the new APIs,
checked a bad import, and restored a 100 KB result through its reference.

Real-provider comparisons are small samples and do not establish a general
cache or efficiency improvement. Native execution is checked on Linux amd64;
other targets have build/compilation evidence. Real image/vision/Exa quality and
long-term continuous operation are not part of these checks.
