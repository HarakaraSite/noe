# NOE v2.14.0

This release completes standard-library roadmap phases 3 and 4: process and
standard-I/O integration, combined cancellation, and asynchronous resource
disposal. It includes breaking JavaScript changes without compatibility
adapters. Public Go packages retain their `/v2` import paths. Go 1.27.2,
go-quickjs v0.32.0, go-intl v0.8.0, and disabled JIT are unchanged.

## Process and standard I/O migration

| Before | v2.14.0 |
| --- | --- |
| `import {spawn} from 'noe:process'` | Import from `node:child_process` or `child_process`. |
| `import {stdin, stdout, stderr} from 'noe:io'` | Import from `node:process` or `process`. |
| Synchronous `process.stdin.read()` or `process.stdout.write()` | Use a Web Stream reader/writer, `Response`, or `pipeTo`. |
| `pipe(source, destination, options)` from `noe:io` | Use `source.pipeTo(destination, options)`. |
| Synchronous stdio `isTTY` facade | No replacement is introduced in this release. |

The `noe:process` and `noe:io` modules and their documentation topics are
removed. Named, default, and bare aliases share their implementations.
Existing `execFile`, `exec`, and synchronous captured-command APIs remain.

`spawn` retains NOE's Promise/Web Streams contract. Await startup to obtain
the child; `stdin` is a byte WritableStream, `stdout` and `stderr` are byte
ReadableStreams, and `exited` resolves to `{code, signal}`. Existing stream
options, asynchronous `kill()`, and idempotent asynchronous `close()` remain.
This does not implement Node.js ChildProcess events or Node Streams.

```js
import {spawn} from 'node:child_process';

await using child = await spawn('printf', ['hello'], {stdout: 'pipe'});
const output = await new Response(child.stdout).text();
const status = await child.exited;
console.log(output, status.code);
```

Named `stdin`, `stdout`, and `stderr` exports are the same stream instances
as the corresponding default/global `process` properties when both stdio
and process information are enabled. Locks are shared across these aliases.
For example, use `await new Response(stdin).text()` to consume all input or
`await stdin.pipeTo(stdout, {preventClose: true})` to copy bytes.
Select `preventClose` according to whether the destination should remain open.

Go profiles still select process information and stdio independently. A
stdio-only profile exposes the streams without global `process` or metadata;
a process-information-only profile has no stdio exports. Worker stdin is EOF,
and closing execution streams does not close borrowed host I/O. Console output
retains its separate endpoint.

## Cancellation and resource cleanup

`AbortSignal.any(iterable)` combines genuine signals, preserving the exact
winning reason, including falsy values. Pre-aborted inputs win in input order;
otherwise the first actual abortion wins. Nested combinations and duplicate
inputs are supported, synthetic events do not propagate, and inactive or
settled dependencies can be collected or unlinked.

Pipe shutdown now interrupts pending reads and backpressure waits, joins
accepted writes before completion and lock release, and coordinates source
cancellation with destination abort while honoring the prevent options.

FileHandles, spawned children, raw connections, socket listeners, and signal
subscriptions implement `Symbol.asyncDispose`. `await using` awaits their
existing `close()` on block exit, return, or an exception. File close still
drains admitted I/O, and child close still stops and reaps a running child.
Explicit `close()` remains supported; forced runtime shutdown is unchanged.

Existing controller/timeout Error defaults remain. Actual abortion now uses
internal event dispatch: overriding a signal instance's `dispatchEvent` no
longer intercepts controller or timeout abortion. Ordinary listeners and
`onabort` retain their behavior. No such override was found in the inspected
NOE or noebot consumers.

## Consumer migration and verification

The [noebot migration instructions](../development/noebot-v2.14.0-migration.md)
identify the two required spawn-import edits, minimum-version update, test
commands, and deployment ordering. A temporary copy of remote noebot revision
`45de74771d9c048448afb1e7f1039b0b45a01443` passed 208 checks with only those
two imports changed. No additional standard-I/O or cancellation migration
was identified there.

Passing implementation evidence is reused: affected unit/integration and
race checks, CLI run/eval/Workers/events and fixture agent tools, external
Go consumers with six-target builds, TypeScript declarations, JS lint, vet,
and independent process/stream/lifecycle reviews. Release verification checks
source and dependency continuity, a clean release-flags native build, and
focused migration smoke. CI builds six CGO-free binaries and publishes
checksums without rerunning the source suites.

See the [roadmap](../development/stdlib-roadmap.md) and
[release checkpoints](release-checkpoints.md). Shared installed executables
and running noebot processes are kept on their existing version during this
publication; the noebot rollout coordinates the executable and source changes.
