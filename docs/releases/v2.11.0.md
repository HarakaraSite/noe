# NOE v2.11.0

This release adds image editing and a separate ChatGPT subscription image
provider. Existing required Go service interfaces and dependencies are unchanged.

## Generate and edit subscription images

`openai-codex-images` provides generation and editing with `gpt-image-2`.
`edit_image`, exported by `noe:image` and `noe:model`, accepts an ordered
`images` array of local paths and saves one validated output atomically.
The source bytes are read through the execution's actual filesystem policy.
Use `read_image` explicitly to attach the saved image to a later model request.
Masks and API-key/OpenRouter editing are outside this release.

Managed credentials use a separate NOE-owned file and native loopback
OAuth/PKCE login. `scripts/auth-codex-images.js` starts the login flow.
Expiry refresh and one same-identity 401 recovery coordinate through file
locking. The `external-readonly` mode can use an existing Codex login without
writing or refreshing that source. It does not fall back to an API key or
the separate public plan-sharing authentication route.

Optional Go `ImageEditor` support is retained through public services,
scoped operations and the CLI's lazy service. Image events and structured
errors distinguish generation and editing, and known usage is counted once
even when cancellation or a later response/save failure occurs.

## Agent guidance and discussion records

Workspace guidance now separates common policy from repository references,
bounds delegated work and reviews, and uses the standalone workflow only
when explicitly selected. Local delivery is complete without a push unless
push was requested. The extension guide is shorter and links its references.
Instruction-source selection and noebot discussion/run records are included;
these records do not introduce a new noebot implementation.

## Verification and distribution

Implementation checks include whole-tree unit tests and vet, focused auth
and image lifecycle race checks, TypeScript declaration checks and external
Go consumers. Independent review findings were corrected and re-reviewed.
An authorized actual subscription workflow generated one image, read it,
edited the original bytes and read the result on subsequent model requests.
Both outputs were visually checked. The actual provider returned 1254 by
1254 PNGs despite the requested 1024 by 1024 size.

Native NOE fresh-login confirmation was explicitly skipped by the user.
Native login and managed refresh have deterministic fixture/race coverage,
without real-account login/refresh confirmation. The successful live image
workflow used external-readonly credentials.

Release preparation reuses valid implementation evidence. The lightweight
CI builds six CGO-free binaries, generates SHA256SUMS and publishes the
immutable tag. Published assets and real public Go-module consumers are
verified after publication. Native execution is Linux amd64; the other five
targets receive build/hash verification.
