# NOE v1.15.2

This patch fixes saved tool-output observation, provider HTTP header overrides, stream cleanup, and symbolic-link operations in embedded filesystems. It also clarifies the built-in agent instructions and updates the Go embedding documentation.

## Runtime fixes

- Saved event-log observation releases a completed tool's output buffer. Reusing a tool-call ID in a later model step no longer mixes earlier output into the latest result.
- Model-specific HTTP header overrides and `null` deletions correctly handle lowercase base headers in custom providers. Normalization is restricted to transport HTTP headers; unrelated request-body parameters retain their existing behavior.
- `noe:io.pipe()` validates a truthy signal before acquiring stream locks. Cleanup still releases both locks if removing the signal listener throws. Existing falsy signal values and structurally compatible signals remain supported.
- Filesystems embedded with `FS.Root` preserve the final symbolic link for `lstat`, `readlink`, removal, and rename operations, instead of acting on its target. Existing outward-link checks, ordinary reads/stat behavior, and unrooted operations are preserved. This fixes entry selection; it does not change the separate nonexistent-path or filesystem-race limitations of `FS.Root`.

## Agent guidance

Built-in instructions distinguish runtime/API constraints from defaults for autonomy, work procedures, output, validation, and model selection. Explicit task or additional system instructions can change those defaults. Agents are directed to keep work proportional to the task and finish when the requested result and necessary checks are satisfied.

Parallel execution is recommended when appropriate for the task and service constraints. The Jev model in the decision example is explicitly illustrative. Context estimates now correctly describe the additional approximation for attached images. Practical `run_js` examples and autonomous decision-model use remain available.

Detailed development, review, and reporting rules are kept in the editable [workspace instruction](../../.noe/instructions/development.md). They are loaded by new agent instances started from this workspace, rather than imposed on every NOE installation. Existing instances retain their original instructions across queue tasks.

Current-entry documentation now describes the public Go `stdlib` and `agent` packages and shared bridge correctly. Dependencies and the pinned go-quickjs engine are unchanged. The executable remains on the v1 release line; this does not publish a v2 Go module.

Validation and the previously observed intermittent network-test `Busy()` assertions are recorded in [release checkpoints](release-checkpoints.md).
