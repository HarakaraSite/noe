# NOE v2.10.0

This release lets each CLI execution choose its external instruction
directories. It also adds GPT-6.1 Terra catalog metadata for the OpenAI
providers. Public Go/JavaScript APIs, Go 1.27.2, go-quickjs v0.29.0,
go-intl v0.8.0 and selected dependencies are unchanged.

## Per-execution instruction directories

Both `noe run` and `noe eval` accept:

- Repeatable `--inst DIR` or `--inst=DIR`: replace the default directory
  list, preserving supplied order and repetitions.
- `--no-inst`: select an explicitly empty external directory list.
- Neither option: retain common plus starting-cwd workspace discovery.

~~~sh
noe run --inst /srv/my-app/instructions --inst ./team-rules app/main.js
noe eval --inst=./team-rules 'console.log("ready")'
noe run --no-inst app/main.js
~~~

The original development-snapshot names `--instruction-dir` and
`--no-instructions` remain compatibility aliases, including both directory
value forms. No `-I` option is added. Old and new names share ordering,
mutual-exclusion and duplicate-empty-selection rules.

Options precede the first operand; `--` ends option parsing. Script
arguments remain unchanged. Relative locations are fixed against the
actual starting cwd, not the entry-script directory or a discovered Git
root. NOE performs no environment-variable or tilde expansion.

Selection changes only the source locations, not execution cwd or access
permissions. Built-in runtime/API facts and explicit `config.system`
remain even with `--no-inst`. Unlisted default directories are excluded
from an explicit replacement selection.

Existing loading rules remain: immediate lowercase .md files in filename
order, concatenation rather than filename overrides, supported symlinks
to regular files, missing directories contributing nothing, and failures
for unreadable sources. Contents load lazily at each instance's first
actual task; queued tasks keep their snapshot and fresh children read
the selected locations anew. Custom Go hosts retain their own
instruction-source/policy control.

The intentionally separated Markdown files and provider-oriented
config.json are not consolidated. There is no live reload, new memory
system or application registry. See the [instruction guide](../instructions.md).

## GPT-6.1 Terra catalog metadata

The OpenAI ChatGPT and API provider catalogs include GPT-6.1 Terra
metadata for model discovery and selection. This is catalog information,
not a guarantee of model availability for every account or a new
provider transport. No dependency update is required.

## Verification and distribution

The original directory-selection feature passed independent plan/code
reviews, deterministic local-provider composition checks, affected-package
vet and coordinated whole-tree validation. A stale removed-REPL help
assertion was corrected, and the entire CLI package passed afterward.

The short names and compatibility aliases passed the complete CLI package,
including actual run/eval agent composition, ordering, empty selection,
lazy behavior, usage errors, alias mixing and unchanged script arguments.
CLI vet, gofmt and diff checks passed. No paid model-provider request was
needed for these feature checks.

Release preparation reuses valid implementation evidence rather than
repeating unrelated source suites. The unchanged lightweight CI builds six
CGO-free binaries, creates SHA256SUMS and publishes the immutable tag.
Published assets, native instruction-option smoke behavior and actual
Go-module retrieval are checked afterward. Native execution here is
Linux amd64; other targets receive CI build/hash verification.

This release request includes local package placement. Only verified
published Linux amd64 assets are installed, with previous executables
backed up and atomic replacement; running processes are not restarted.
External instruction files remain user-controlled and are not installed
or overwritten by the binary.
