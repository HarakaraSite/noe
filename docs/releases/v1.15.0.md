# NOE v1.15.0

This release adds task-specific completion waits for JavaScript agent workflows and keeps automatically named event logs in the workspace's `.noe/events/` directory.

## Wait for an individual task

`wait_task({agentId, commandId})` waits for one accepted initial or queued task and returns `{runId, commandId, state, answer, error?, errorDetails?}`. It does not wait for the instance to become idle or stop. A later queued task cannot overwrite the requested outcome.

Completed outcomes remain available within the owning evaluation, including after an instance stops. Repeated and concurrent waits receive the same result without consuming it. Task failures and cancellations resolve as data; invalid, unknown, or unowned IDs reject. Tasks cancelled before starting have an empty `runId`.

`spawn_agent` now returns `{agentId, commandId}` when an initial instruction is supplied. Idle launches still return only `{agentId}`. Existing callers should pass `{agentId}` explicitly to `observe_agent` or `interrupt_agent`, rather than forwarding the complete spawn receipt.

The API is available in `noe:agent`, generated `run_js` bindings, hook callbacks' `api.agents`, and the shared Go agent bridge. It uses completion notifications without polling, extra model calls, or wait-specific observe/JSONL events. Cancelling only a wait does not cancel its target; existing owner cancellation and cleanup still apply. Queue acceptance, FIFO ordering, human CLI commands, and observation output retain their existing behavior.

## Workspace event logs

Bare `--events` now creates `.noe/events/noe-events-<date>-<time>-<id>.jsonl` under the starting working directory, creating the directories when needed. Previously, the automatically named file was created directly in that directory.

Explicit `--events=path` continues to append to the specified file, `--events=-` writes JSONL to stdout, and omitting the option does not save events. Parent and owned child tasks share the parent's configured event stream.

## Examples and documentation

The [Jev-gated task-loop example](../../examples/agent/task-loop-jev/README.md) combines plan review, revision, implementation, testing, and code review in JavaScript. It uses `queue_agent` and `wait_task`, with Jev selecting whether to revise or proceed. Requirements, deliberately incomplete starting files, tests, and execution instructions are included.

The English bundled reference and agent instructions document the new API. Local six-target release checks now use link-free compilation; distribution binaries are built by the tag-triggered workflow.

The executable remains on the v1 release line; this does not publish a v2 Go module. Dependencies and the pinned go-quickjs engine are unchanged. Validation evidence is recorded in [release checkpoints](release-checkpoints.md).
