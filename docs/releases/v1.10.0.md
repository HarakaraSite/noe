# NOE v1.10.0

NOE now maintains and uses its own standard library snapshot, based on go-quickjs v0.27.0. Normal scripts, Workers, agent tasks, and `run_js` all use the same maintained implementation. The JavaScript engine remains the pinned go-quickjs dependency.

## Standard library ownership

The imported source, tests, fixtures, WebSocket protocol support, and MIT license are kept in `internal/stdlib`. Its [provenance record](https://forge.harakara.site/littleisland/noe/src/tag/v1.10.0/internal/stdlib/UPSTREAM.md) identifies the upstream version, commit, checksum, and local adaptations. Bundled English API docs and the agent's initial instructions now describe the engine and the maintained standard library separately.

Existing JavaScript APIs, supported module names and aliases, configuration, Worker behavior, cancellation, and resource cleanup retain their contracts. No script migration is required. The maintained library is currently an internal Go package.

The observation UI also replaces its `golang.org/x/term` dependency with small OS-specific terminal-width helpers. Environment overrides and width fallback behavior are preserved.

## Validation and distribution

The [runtime migration record](https://forge.harakara.site/littleisland/noe/src/tag/v1.10.0/docs/development/stdlib-step2-runtime-implementation.md) includes exact before/after API comparisons in main, Node-style Worker, nested Worker, and Web Worker contexts; unit tests, race detection, CLI and fixture-agent E2E, vet, and six-target compilation. Independent code review found no P2-or-higher issues. A real OpenCode Go / `deepseek-v4.1-flash` agent also completed a file-read, aggregation, write, verification, and final-answer task through `run_js`.

Downloads cover Linux, macOS, and Windows on amd64 and arm64, with `SHA256SUMS`. Native execution is verified on Linux amd64; other targets have cross-build evidence.
