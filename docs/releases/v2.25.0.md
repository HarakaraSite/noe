# NOE v2.25.0

This release updates go-quickjs from v0.32.0 to v0.37.1 and go-intl from
v0.8.0 to v0.9.0, incorporating the integration in `c29d466`.
JIT remains disabled. The Go `/v2` module path, host capabilities and existing
native backends are unchanged.

## Engine corrections and improvements

The update fixes a nested-loop error affecting ordinary execution without JIT:
an inner loop with continue before a later break condition could stop early
and silently omit results. Main runtimes, Workers and node:vm now produce the
correct result. Upstream also improves object allocation, repeated Program and
Realm memory retention, JSON processing, compilation and constant array literals.
These are upstream improvements; no NOE performance benchmark is claimed.

## Standards behavior and migration

Error and fresh DOMException instances inherit the stack accessor instead of
having an own stack property. Stack strings remain readable and cloning retains
the trace. Code that inspects own properties must allow this new structure.
Iterator helpers validate closing operations. A DataView made out of bounds by
shrinking its buffer reports byteLength and byteOffset as zero. Temporal adopts
the newer annotation grammar and ISO PlainMonthDay overflow rules. NOE accepts
these standards-mode changes without enabling WithNodeQuirks.

Web Crypto subtle methods now reject resizable ArrayBuffer-backed inputs with
TypeError, including views into those buffers. This follows Web IDL and prevents
an out-of-bounds DataView from silently hashing empty data after the engine
getter change. In-bounds resizable inputs previously accepted are rejected too.
Copy the intended bytes into a fixed Uint8Array before passing them as data,
raw key material or algorithm fields such as salt. Fixed-buffer view offsets,
valid empty DataViews, input snapshots and rejected-Promise behavior remain.

## Verification and scope

Implementation verification covers unit tests, CLI E2E, affected race checks,
main/Worker/realm regressions, production interruption, standalone Go consumers,
unmodified jose 6.2.15 and Node interoperability, and six compilation targets.
Two outdated HTTP E2E fixtures were corrected to preserve lowercase patch, as
the existing Request method contract requires; they pass on both engine versions.
Completed source verification is reused for release preparation and lightweight
CI builds six binaries and SHA256SUMS from the immutable tag.

The existing Iterator.from wrapper closing divergence remains. Full
BodyInit/BufferSource conversion, complete Web conformance, JIT enablement and
other stdlib expansion are outside this release. Other target binaries are
compiled but not executed natively. No live provider request is needed.

Publication includes verified installation at both existing vm201 executable
paths, with previous binaries retained. Other hosts, running services and
noebot are excluded. See the [integration record](../development/go-quickjs-v0.37.1-upgrade.md)
and [release checkpoints](release-checkpoints.md).
