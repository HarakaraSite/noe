# NOE v1.16.0

This release keeps agent sessions stable across queued tasks, restores ChatGPT
prompt-cache affinity, and adds explicit controls for delegation and result delivery.
It also streamlines the test suite while retaining current behavioral coverage.

- Each running agent instance now uses one session ID across queue tasks. Task
  run IDs remain independent. ChatGPT requests send that ID in the `session_id`
  header in addition to the existing body cache key. A fixed-input live check
  reported 4,608 cached tokens out of 4,791 input tokens on the second request
  (96.18%); cache rates in ordinary changing conversations can differ.
- A child agent cannot delegate by default. Its owner can grant permission with
  `{allowDelegation:true}` when launching it. The shared Go admission path checks
  both `spawn_agent` and `run_agent`; permission is not automatically inherited.
- `NOE_CONTEXT_STATUS` is retained as user-role observation history with its
  assistant/tool exchange, preserving sent prefixes and trimming whole exchanges.
- `wait_task` and live `observe_agent` accept `includeAnswer:false` to return
  completion metadata and answer byte counts. `read_task_result` reads retained
  answers by UTF-8 byte range without another model call. Default answer delivery
  and existing agent lifetime rules remain unchanged.
- Tests now follow these contracts, share the managed-task CLI build, and keep
  error/stream classification separate from retry timing. Startup/RSS measurement
  is separated from regression checks. Completed investigation branches and old
  low-level/OpenCode prototypes are retired, with their findings preserved.

No provider dependency upgrade or v2 Go-module publication is included. The
executable remains on the v1 release line. Delegation workflow guidance remains
an external instruction while its behavior is evaluated.

Release checks and published artifact verification are recorded in the
[release checkpoints](release-checkpoints.md).
