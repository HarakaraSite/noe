# NOE v2.32.0

## Search the built-in API reference

`searchDocs(query)` in `noe:docs` finds API entries by name or task keywords.
It returns up to five matches with a topic, member ID, and short excerpt.
Pass the topic and member to `docs` for the full entry. Search works in
the main runtime and Workers.

```js
import { docs, searchDocs } from "noe:docs";

const [match] = searchDocs("read part of a file");
export default match ? docs(match.topic, match.member) : null;
```

The [built-in reference](../api.md) includes a `FileHandle.readAt` example for
reading bytes at an offset.

## Run agent scripts with deadlines and progress

Set `timeoutMs` in the initial `// @noe:` comment to limit one `run_js`
call. An expired call returns a timeout result with the output it captured.
Set `saveData: true` to save the complete default export when its JSON
exceeds `outputBytes`. The result includes a `dataFile` reference a later
call can read.

`--observe` displays sampled stdout and stderr while a script runs. The
same samples appear as `run_js.progress` events in JSONL. See
[execution results](../execution-results.md) for the options and fields.

## Runtime, standard library, and agent

- Runtime installations reuse compiled built-in programs. Text encoding,
  live Headers iteration, local storage writes, SQLite row conversion,
  and full FileHandle reads do less intermediate work.
- The agent reuses conversation context analysis, image metadata, and
  queued history. It honors an accepted cancellation before publishing
  queued history and analyzes logs incrementally.
- Chat requests are encoded in one pass. Managed Responses WebSocket
  requests reuse configuration during continuation and replay.
