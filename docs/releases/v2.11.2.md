# NOE v2.11.2

This maintenance release updates go-quickjs from v0.31.1 to v0.32.0 with
JIT disabled and synchronizes two standard-library lifecycle tests with
upstream. NOE retains Go 1.27.2, go-intl v0.8.0, and its existing public APIs.

## Updated interpreter

The engine improves regular-expression matching, JSON.stringify allocation,
compilation of large JavaScript bundles, literal switch dispatch, and several
built-in calls. These improvements include paths used without JIT. Upstream
benchmark results are not measurements of NOE workloads.

Array.prototype.join and global regular-expression replacement now throw
RangeError: Invalid string length on previously unchecked paths whose result
exceeds the engine's string-length limit. The new WithJITBackground option
is unused by NOE: normal runtime and Worker constructors retain quickjs.New(),
and distribution builds omit the quickjs_jit tag.

NOE's maintained standard-library implementation is unchanged. Two lifecycle
tests now wait for readiness with RunUntil instead of running the loop in
20 ms slices, which could interrupt an asynchronous callback permanently.
The tests delay a request until its child process has started, wait for its
arrival, and simulate a 30 ms file-operation delay to exercise both regressions.

The release also includes previously committed clarification of the remote
callback-paste instructions in the conversation and image authentication
helpers. This changes guidance, not authentication behavior.

See the [upstream release](https://github.com/go-quickjs/go-quickjs/releases/tag/v0.32.0)
and [lifecycle test fix](https://github.com/go-quickjs/go-quickjs/commit/29c06274f4a9a837646e463f37a557ae6834a8c2).

## Verification and distribution

Implementation verification passed the combined unit and local CLI E2E suite,
including external Go consumers, full vet, repeated lifecycle tests, focused
lifecycle race checks, and module verification. Release preparation reuses
those results and checks the configured version, native build, and smoke
behavior. No real-provider requests are needed.

The lightweight CI builds six CGO-free binaries, creates SHA256SUMS, and
publishes the immutable tag. Published checksums, build information, native
smoke behavior, and public Go-module consumers are checked after publication.
The verified Linux amd64 asset is installed into repository-root ./noe and
/home/agent/.local/bin/noe with backups and atomic replacement. Running
processes adopt the new executable when restarted normally. Other targets
receive build and checksum verification without native execution here.

See the [release checkpoints](release-checkpoints.md).
