# NOE v1.6.0

This release adds automatic trimming of agent execution history and per-request context usage/budget notifications. Long tasks can keep running without resending every old tool exchange, while the original task and instructions remain available.

## Automatic context management

- Automatic trimming is enabled by default. Use `contextPolicy: {retainRatio: 0.1}` to make the default retention target explicit, or `contextPolicy: null` for notifications without trimming. `retainRatio` must be greater than zero and less than one.
- Preserve the complete system instructions, original task, every applied steering instruction, and the newest completed exchange. Remove older assistant responses with all their matching tool results as complete blocks, keeping reasoning, signatures, native response items, and provider extensions intact in retained history.
- Trim immediately before a model request, after `beforeModelRequest` hooks and any delivered steering instructions. Recalculate the notification from the trimmed input. Repeated preparation does not invoke the hook again or consume an extra model request.
- Keep saving optional. There is no mandatory checkpoint, summary model, archival step, or extra model turn. One-shot `noe:decision` requests are outside this mechanism and retain their original state and questions.

The target is approximately 10% of the prior execution history, but the newest complete block is always retained. Large recent blocks or protected instructions can prevent reaching the target or budget; NOE reports that condition and continues through the normal provider path. It does not split tool results or introduce a new hard task limit.

## Budgets and inheritance

`contextBudget.inputTokens` continues to mean total input, including fixed instructions. **Behavior change from v1.5.0:** with automatic policy enabled, an explicit input budget now also triggers history trimming. Set `contextPolicy: null` to retain the previous notification-only behavior. `contextBudget: null` clears an explicit budget and does not disable automatic policy.

When the catalog window and response reserve are known, the execution budget is about 90% of the remaining window after fixed input, request-only information, and the reserve. An explicit total-input budget caps that allowance. With an unknown window and no explicit budget, NOE uses a 1,000,000-token total-input fallback; it does not infer that the model supports that capacity. A known window with an unknown response reserve caps total input at 90% of the window.

`contextPolicy.responseReserveTokens` is an optional positive safe integer for budget calculation; it does not set the provider's output limit. A positive `maxTokens` also reserves output space, using the larger value when both are supplied. Otherwise the catalog maximum output is used when available.

Children inherit policy, including explicit `null`, unless overridden. Each child recomputes its budget for its own model and fixed input. Queued tasks keep the instance configuration but start with fresh history and trim counters. OpenRouter's DeepSeek V4.1 Flash catalog now includes its confirmed context window; unconfirmed values are not copied across providers.

## Observation

- Model notifications and context snapshots distinguish execution-history usage/budget from total input and previous measured usage. Estimates use JSON UTF-8 bytes divided by four; cached input is still input.
- `--observe` and `noe observe` show execution budgets and actual trim events. JSONL and live/saved `observe_agent` retain trim counts, the latest trim, before/after estimates, and causal IDs.
- Pending trim notifications and causes survive steer-only preparation until an actual provider request is admitted. Candidate history is committed and recorded before installation in task JS, preserving the committed-context fact if the run is interrupted before its next request.

## Validation and downloads

Implementation slices received tests and code review, followed by integration and overall review. Local fixtures cover complete tool blocks, reasoning fields, steering, interruption, parent/child/grandchild inheritance and overrides, model-specific budgets, queue resets, and run/eval/REPL observation.

Authorized OpenCode Go / DeepSeek V4.1 Flash trials completed a four-file task across five trims. Controlled 10%/20% retention and disabled trimming were compared with a natural task. One initial 20% trial produced string IDs; that failed output validation is retained separately from a successful retry with an explicit numeric-ID requirement. No trial created an extra memory file, and large newest blocks limited the observed reduction. These small trials do not establish an optimal retention ratio or general performance improvement.

Dependencies and the release workflow/profile are unchanged from v1.5.0. Release gates include unit tests, Linux PTY E2E, vet, race detection, and six CGO-free builds. Downloads cover Linux, macOS, and Windows on amd64 and arm64 with `SHA256SUMS`. Native execution on the other platforms remains unverified. See the [release checkpoints](https://forge.harakara.site/littleisland/noe/src/tag/v1.6.0/docs/release-checkpoints.md).
