# NOE v2.8.1

This compatibility release supplies `import.meta.url` so an ES module can
compute asset URLs relative to its own location. Go 1.27.2, go-quickjs
v0.29.0, go-intl v0.8.0 and all selected dependencies are unchanged.

## Module-relative URLs

- File modules receive encoded file URLs for their resolved paths, including
  spaces, non-ASCII characters and URL punctuation.
- HTTP/HTTPS modules retain their final canonical URL after redirects,
  including query and fragment identity. Static/dynamic imports and aliases
  keep the existing module namespace and evaluation rules.
- Module Workers use the same metadata setup. File entries and eval entries
  are covered.
- Virtual run_js/embedding entries use a synthetic `<virtual-entry>.mjs`
  file URL under the execution cwd. CLI eval retains its synthetic
  `<eval>.js` entry URL. No corresponding file needs to exist, and the
  original diagnostic name is unchanged.
- Rooted filesystem profiles expose execution paths, not the host's physical
  root. Host-defined/custom-loader IDs follow the documented metadata rules.
- Go hosts can replace the metadata hook in Profile.Initialize or after
  Attach; preparation does not overwrite the host hook.

```js
const assetURL = new URL("./asset.txt", import.meta.url);
```

Computing a URL does not fetch or read an asset. Existing filesystem/HTTP
capabilities and relative import resolution are unchanged. This release
does not add import.meta.resolve/main/dirname/filename, npm discovery,
CommonJS support, TypeScript transformation or general Node/Web API
compatibility. Existing URL and file-URL helper limitations remain separate.

See the [metadata guide](../import-meta.md) and
[implementation record](../development/import-meta-url-implementation.md).

## Repository helpers and examples

- The external filename-discovery helper at `.noe/lib/find/find.js` prefers
  fd and falls back to GNU-compatible find only when fd is absent. It
  supports basename globs, type/depth filters and bounded structured output.
  This is a repository JS helper, not a new built-in module.
- The external `ls()` helper now returns up to 200 entries by default;
  explicit limits and continuation offsets remain available.
- A small, version-pinned `@lukeed/ms` URL-import example and its sources,
  selection rationale and usage are included.
- The esbuild suitability investigation is recorded. esbuild is not added
  as a runtime dependency, and TypeScript support is not implemented.

## Validation and distribution

Implementation validation passed the full local unit suite, related CLI
and agent URL-import E2E, focused public Go/Worker/HTTP metadata tests,
independent review, formatting and documentation checks. The filename
helper's fd/find/fallback/error/output-limit tests, file helper tests, and
sample execution/lint also passed. No paid model call was required.

Release preparation reuses this evidence instead of repeating full suites.
The unchanged lightweight CI builds six CGO-free distribution binaries,
creates SHA256SUMS and publishes the immutable tag. Published artifacts,
native metadata behavior and actual Go-module retrieval are checked before
local installation. Native runtime verification is Linux amd64; other
targets receive build/checksum verification, not native execution here.

See the [release checkpoints](release-checkpoints.md).
