# NOE v2.1.1

NOE reduces redundant agent processing and corrects Worker shutdown after
`parentPort.close()`. Public CLI commands, JavaScript modules and Go API
signatures are unchanged. Go 1.27.2, go-quickjs v0.28.0 and the dependency
versions are unchanged; experimental JIT remains disabled.

## Worker shutdown

Closing a Worker's parent port ends messaging, rather than the Worker itself.
Previously, the close notification could report exit and remove the Worker
from its owner's shutdown list before its runtime and initializer cleanup
finished. This could let a managed execution return with cleanup still pending.

Worker exit now waits for runtime cleanup and Worker accounting to finish.
Errors and explicit exit codes still reach the parent after port closure, in
order after previously posted messages. Parent shutdown retains and joins
Workers whose cleanup is still running.

## Agent processing

Managed tasks reference the Go host's committed conversation by revision rather
than resending the full transcript in each step's begin, preparation and model
requests. Stale revisions and unowned references are rejected. Trim approval,
steering, queue continuity, image ownership and opaque provider fields are
preserved; model services receive independent request buffers.

The typed Go Client bypasses the internal JSON adapter while sharing its
acceptance, ownership, cancellation and request-joining boundary. Configuration
validation, mutable-input snapshots, independent response snapshots, omitted
answers and the former JSON path's invalid UTF-8 normalization are preserved.

Image-reference validation no longer creates discarded data URLs. Context
preparation reuses measurements and block weights, and identical history JSON
avoids repeated semantic decoding. CLI observation output reuses I/O adapters,
and private SSE snapshots share immutable event payloads.

Waiting file observation skips JSON analysis when the file bytes are unchanged.
It still detects replacements, truncation and same-size rewrites. Two reusable
raw buffers are retained for the wait, so their memory scales with log size.

## Validation

The changes passed independent review, the full unit/E2E suite, race checks,
sustained Go Client waits, vet and compilation for all six distribution targets.
External stdlib and agent consumers were checked through local replacement and
module-artifact paths. The previously failing stdlib artifact also passed 100
runs with eight concurrent processes after the Worker fix.

Regression tests block Worker cleanup and verify that neither exit nor managed
execution completion runs ahead of it. Restoring the previous Worker code makes
these tests fail, including the port-close error and exit-code cases.

See the [implementation record](../development/processing-simplification.md)
and [release checkpoints](release-checkpoints.md) for detailed evidence and
publication validation. Native execution is checked on Linux amd64; the other
targets have compilation/build evidence. No paid model-provider calls were
needed, and no end-to-end agent performance improvement is claimed.
