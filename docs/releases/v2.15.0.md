# NOE v2.15.0

This release adds filesystem watching, source maps enabled by default, local
and HTTP data imports, import-map prefixes/scopes, and custom WebSocket
handshake headers. It covers stdlib roadmap phases 5–7 and the first phase 9
slice. Web Crypto expansion remains deferred until a concrete SDK needs it.

## Filesystem watching

`node:fs.watch` supplies callback/EventEmitter notifications, and
`node:fs/promises.watch` supplies an async iterator. Both use the selected
filesystem and a shared native backend, with change/rename events, basename
filenames, abort signals, close/disposal, bounded queues, and runtime cleanup.
The callback API supports ref/unref; the iterator opens lazily on first next.
The initial implementation is nonrecursive. Unsupported recursive modes are
reported explicitly. See the [watch contract](../development/stdlib-fs-watch.md)
for queue/overflow behavior, filename encodings, cancellation, and Go profiles.

## Source maps enabled by default

NOE-owned main, Worker, and agent run_js runtimes map Error.stack and stack
locations in diagnostics back to original sources. Inline maps and readable
local sidecars are supported through the selected filesystem. Missing or
unreadable maps fall back to generated positions. Remote modules can use
inline maps; NOE does not fetch remote sidecar maps.

This changes visible stack locations when a map is available. Syntax-error
position fields remain generated positions, and custom Error.prepareStackTrace
callbacks retain raw CallSites. Borrowed runtimes attached through the public
Go API retain the caller's source-map settings. This does not enable TypeScript
execution. See the [source-map record](../development/stdlib-source-maps.md).

## Data imports and import maps

Static and dynamic import attributes select JSON, text, or bytes through the
existing engine. Each data module exports a default value. JSON aliases share
the parsed mutable object, while bytes uses an immutable ArrayBuffer.

```js
import settings from "./settings.json" with { type: "json" };
import template from "./templates/email" with { type: "text" };
import payload from "https://example.com/payload" with { type: "bytes" };

const { default: more } = await import("./more.json", {
  with: { type: "json" }
});
```

Local filenames have no suffix restriction. A plain import always means
JavaScript; filenames and HTTP Content-Type do not select a data type.
There is no extension completion, CommonJS loading, or TypeScript conversion.

Import maps add slash-terminated bare prefixes and referrer scopes. Exact
rules precede the most specific prefix; scopes fall back from the most
specific matching referrer scope to outer scopes and global imports. Relative
targets stay anchored to the import-map document. Prefix expansion cannot
escape its mapped base. Built-ins remain reserved. Immutable map snapshots,
including nested scopes, reach Workers, agent bootstrap/run_js, and children.
Go embedding adds `LoaderOptions.Scopes`; external unkeyed LoaderOptions
literals should use field names. Existing in-repository uses already do so.

### HTTP compatibility changes

HTTP response-body bytes are now passed unchanged to the engine, matching
local source handling. This replaces the previous JavaScript/text MIME
allowlist, strict UTF-8 check, and leading-BOM removal:

- Missing, malformed, or arbitrary MIME metadata is accepted. A plain import
  can execute JavaScript regardless of its response MIME.
- Text retains a leading BOM. Bytes preserves BOMs, zero bytes, and invalid
  UTF-8. Transport decompression still applies: bytes reflects response-body
  data, not compressed wire bytes.
- BOM-prefixed JSON fails the pinned engine's parser, including JSON previously
  served through a text MIME with its BOM removed by the loader.
- Invalid UTF-8 reaches engine interpretation rather than an HTTP-loader error.

HTTP status checks, request/redirect policy, timeouts, body limits, and host
cancellation retain their roles. Standard Worker entries remain local. No
engine patch or upstream API change is required. See the
[module guide](../import-map.md), [HTTP policy](../url-import.md#http-source-interpretation),
and [implementation record](../development/stdlib-module-loading.md).

## Custom WebSocket handshake headers

The NOE constructor extension adds an optional third argument. The second
argument remains the subprotocol slot:

```js
const socket = new WebSocket("wss://example.com/feed", undefined, {
  headers: { Authorization: "Bearer <token>" }
});
```

Headers accepts records, iterable pairs, or Headers instances, copied
synchronously per connection. Authorization, Origin, Cookie, and custom fields
can be supplied explicitly. The connection owns its generated handshake and
HTTP framing fields. Invalid headers throw TypeError before connecting,
without including header values in validation errors.

Existing valid one/two-argument calls keep their behavior. Protocol names now
require HTTP token syntax: malformed names throw SyntaxError before connection
instead of entering a malformed handshake or failing asynchronously. An
unrelated non-object third argument can now throw TypeError because that slot
is recognized as options. URL policy, TLS, timeout, lifecycle, and Worker
inheritance use the existing Go WebSockets configuration. See the
[header contract](../development/stdlib-websocket-headers.md).

## Verification and distribution

Implementation evidence covers affected unit and race suites, CLI/Worker/agent
routes, WS/WSS, map and filesystem capability boundaries, public Go consumers
with standalone module artifacts, type declarations, vet, and bounded reviews.
Release verification reuses those results, checks source continuity, builds a
clean native candidate, and exercises the new features with focused smoke.
CI builds the six distribution targets and publishes checksums without
repeating local source suites. Native execution verification is Linux amd64;
other targets receive build and checksum verification.

The public Go packages retain the `/v2` module line. Go 1.27.2, official
go-quickjs v0.32.0, go-intl v0.8.0, and disabled JIT remain in use. Native
filesystem watching adds fsnotify v1.10.1. See the
[release checkpoints](release-checkpoints.md) and [roadmap](../development/stdlib-roadmap.md).
