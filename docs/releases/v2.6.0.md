# NOE v2.6.0

This feature release adds steer-aware grouped waiting for delegated agent tasks.
A parent can receive guidance while its children are still running, return from
its waiting tool and decide how to respond. Existing completion-only APIs remain
compatible. Go 1.27.2, official go-quickjs v0.28.0 and other dependencies are unchanged.

## Grouped waiting that returns control to the parent

- New JavaScript `wait_tasks({tasks: [{agentId, commandId}, ...], includeAnswer?})`
  waits for the entire selected set or returns early on unapplied guidance to
  the caller's owner run. The owner is derived from its existing scope.
- Results distinguish `reason: "completed"` and `reason: "steer"`, with ordered
  `completed` outcomes, `pending` IDs and the owner `runId` when present.
  Retained outcomes can still be read repeatedly; failed/cancelled tasks remain
  outcome data. `includeAnswer: false` omits answers and reports their byte sizes.
- Guidance ends the wait itself, not the parent, its Operation or its children.
  It is not consumed by waking the wait: existing history checkpoints and steer
  application deliver it to the parent's next model request.
- On a steer return, export/return the result and finish `run_js`. Let the model
  read the instruction and choose whether to observe, steer, cancel or stop a
  child. Do not immediately re-wait inside the same tool.
- Trusted-host and ordinary script-origin guidance both wake the wait. No
  periodic polling or extra model calls are needed while nothing changes.
- The same entry point is available through the public Go
  `Client.WaitTasks(ctx, WaitTasksRequest)`, JSON/typed dispatch and hook-scoped
  JavaScript APIs. Public declarations, bundled docs, model-facing facts/policy
  and the parallel-agent example describe the recommended flow.

`wait_task` remains completion-only. Outside an owner run, `wait_tasks` waits for
all selected tasks. Request/owner cancellation is an error, not a steer result.
This is not an interrupt mechanism for arbitrary JavaScript, model requests or
other unrelated blocking tools; it does not add deadlock detection or automatic
child termination. The example Web UI is unchanged.

See the [agent API](../api.md#実行中taskへの指示と停止) and
[implementation record](../development/steer-aware-wait-implementation.md).

## Validation

Deterministic fixtures with the real executor held two children unfinished and
confirmed that parent guidance ends the wait/tool, reaches the next parent model
request once, and leaves the children alive. The parent then explicitly cancelled
one child and steered the other through result retrieval. Both trusted-host and
script-origin routes passed.

Related unit tests cover pre-existing guidance, accepted-event publication,
completion races, repeated guidance and re-waiting, ownership checks, cancellation,
owner shutdown and retained results. Full unit/E2E, affected-package race tests,
JavaScript lint, public declaration checks, formatting and whitespace checks passed.
Independent code review has no unresolved P2-or-higher finding.

A natural history trim was also observed during implementation; progress was
restored from the saved task/implementation records. No context-budget, trim-policy
or cache-setting change is included in this release.

Release preparation reuses those results. The unchanged lightweight CI builds six
distribution binaries, generates SHA256SUMS and publishes the immutable tag.
Native execution verification is Linux amd64; the other targets receive CI build
and checksum verification. See the [release checkpoints](release-checkpoints.md).
