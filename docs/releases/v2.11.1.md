# NOE v2.11.1

This maintenance release updates go-quickjs and makes image sign-in follow
the conversation helper's callback-paste workflow. JIT remains disabled.

## Updated interpreter

The engine moves from go-quickjs v0.29.0 to v0.31.1. go-intl remains v0.8.0,
and NOE retains Go 1.27.2 and its existing public APIs. The update improves
interpreter class/property execution, fixes a dictionary-prototype crash and
detects cancellation sooner during slow loop turns. Changes in intermediate
engine releases also affect stack-frame naming, BigInt limits/error formatting
and constructor semantics. Performance figures published upstream are not
measurements of NOE workloads.

NOE's maintained standard-library snapshot and its local fixes are unchanged.
No `quickjs_jit` build tag or `WithJIT` option is added. Normal runtime and
Worker constructors continue using the interpreter. Implementation verification
confirmed that all six distribution targets select the disabled JIT code.

See the [upgrade and verification record](../development/go-quickjs-v0.31.1-upgrade.md).

## Paste remote image callbacks

`scripts/auth-codex-images.js` now supports `login`, `complete` and `help`,
with short terminal messages matching the conversation helper. From the NOE
distribution root, keep this running in VM terminal A:

```sh
noe run --no-inst scripts/auth-codex-images.js login
```

Open its authorization URL in the Mac browser. Copy the full redirected
loopback URL from the address bar, then run in VM terminal B:

```sh
noe run --no-inst scripts/auth-codex-images.js complete
```

Paste the URL, press Enter and then Ctrl+D. The original login process still
owns code exchange, identity validation and credential saving. Check terminal
A for final save success. Use the same optional credential-file in both
commands. SSH port forwarding, Python and a separate curl command are not
required for this flow.

Image login tries registered callback port 1455, then 1457 if the first is
unavailable. Existing listeners stay running. If both are occupied, the error
explains how to retry. Private pending records are unique to each attempt, so
an older login's cleanup cannot delete a newer login's record. Callback/code/
token data is omitted from helper error output. Image credentials remain
separate from conversation credentials and the active Codex application's file.

The paste workflow and native exchange/save were verified with separate
processes and local OAuth fixtures. Default-port fallback and native callback
delivery were exercised with the actual CLI. Real-account browser sign-in on
port 1457 remains unverified. See the [image guide](../agent-images.md).

## Verification and distribution

Existing implementation unit, E2E, vet, lifecycle race, external consumer and
six-target compilation evidence is reused. An instruction-sensitive E2E
fixture failed identically on the old and new engine; its fixed-budget test
now disables external instructions, and passes on both versions. Independent
reviews found no unresolved actionable integration findings.

The lightweight CI builds six CGO-free binaries, creates SHA256SUMS and
publishes the immutable tag. Published assets and actual public Go-module
consumers are verified after publication. The verified published Linux amd64
asset is installed into repository-root `./noe` and
`/home/agent/.local/bin/noe` with backups and atomic replacement. Running
processes are not restarted. Other targets receive compile/build/hash
verification, without native execution here.

See the [release checkpoints](release-checkpoints.md).
