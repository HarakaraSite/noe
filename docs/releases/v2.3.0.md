# NOE v2.3.0

NOE adds separate structured execution data and diagnostics, API declarations
for its standard and agent libraries, and a guide to checking generated
JavaScript with existing Biome and TypeScript installations. Go 1.27.2,
upstream go-quickjs v0.28.0 and all dependency versions are unchanged.

v2.2.0 was withdrawn. Its version number is intentionally skipped to avoid
confusion with previously downloaded artifacts and cached Go modules.

## Execution results and migration

`run_js` now uses explicit ES module imports, including agent helpers:

```js
// Return configured model identifiers.
import { list_models } from "noe:agent";

const models = await list_models({kind: "agent"});
export default models.map(({provider, model}) => ({provider, model}));
```

**Migration is required for code using implicit agent bindings or parsing NOE
diagnostics from stderr.** Import helpers from `noe:agent` explicitly and read
the separate `diagnostics` field. Actual stdout/stderr writes retain their
existing capture behavior.

Use `export default` to return structured `data`. No default export omits the
field; explicit null returns `data: null`. A default Promise or thenable is
awaited, while functions are not called automatically. JSON conversion happens
once; conversion failures do not replay code or its side effects.

Diagnostics report NOE's observed code, stage and message, with available
stack, source position and exception details. Command stdout/stderr are kept
inside exception details, including base64 for byte output. Missing source
positions are not inferred. Hooks, provider history, JSONL events and CLI
observation receive the separate fields; task execution diagnostics also have
an `execution.diagnostic` event.

Go `stdlib.Result` adds `Data` and `Diagnostics`. Existing error classification
and native Go causes remain available. Consumers using positional Result
literals must switch to named fields. See the
[execution and migration guide](../execution-results.md) for the full contract.

## API information and optional static checks

The source distribution includes separate
[standard-library](../../stdlib/types/noestdlib.d.ts) and
[agent-library](../../agent/types/noeagentlib.d.ts) declaration files. Embedded
docs list public names, aliases, declaration paths and Profile/binding
requirements without loading the documented APIs. Declarations describe the
supported API surface, not the capabilities of every execution Profile.

The [JavaScript checks guide](../javascript-checks.md) explains how to use
existing Biome/tsc installations and the declarations. Neither tool is a new
NOE dependency, automatic check or installation step. Missing tools and failed
setup remain distinct from passing checks; static success does not guarantee
runtime success.

## Validation

Implementation checks covered affected unit/race tests, ordinary CLI E2E,
declaration fixtures, external stdlib/agent consumers through local and module
artifact paths, and a deterministic docs → static checks → run_js → runtime
repair flow. The agent-server fixture was migrated to explicit imports and
its three cleanup paths passed.

Existing valid results are reused for this release. The optional MCP SDK
bundle check and real-provider suites were not run; no paid provider requests
were made. Native execution evidence is Linux amd64. CI builds all six
distribution binaries, creates checksums and publishes them without repeating
local source tests. See the [implementation record](../development/ai-execution-contract-implementation.md)
and [release checkpoints](release-checkpoints.md) for evidence and publication
verification.
