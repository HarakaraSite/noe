# NOE 次の機能候補

この候補一覧はv1.0.0時点の検討記録です。その後のgo-quickjs標準ライブラリ全体の導入により、外部コマンド・ストリーミング・暗号とハッシュは利用可能になりました。現在の対応は[APIリファレンス](api.md)を参照してください。import map・HTTP URLからのimportは引き続き未対応です。

当時のNOE v1.0.0以降の候補として、外部コマンド、ストリーミング、import map、HTTP URLからのimportを検討する。以下は優先順の案で、詳細仕様とインクリメントの範囲は着手時に決める。

## v1.0.0時点の優先順案

| 順番 | テーマ | 目的 | 最初に検討する範囲 |
| --- | --- | --- | --- |
| 1 | 外部コマンド | 既存ツールとファイル・HTTP処理を組み合わせる | コマンドと引数、stdin、stdout・stderr、終了コード、実行中断 |
| 2 | ストリーミング | 大きなファイルやHTTP bodyを全量保持せず扱う | ファイルとHTTPクライアントの段階的な読取り・書込み |
| 3 | import map | ローカルモジュールに名前を付け、配置変更を吸収する | CLIで指定するimport mapとローカルファイルの解決 |
| 4 | HTTP URLからのimport | URLで公開されたJSモジュールを読み込む | モジュール取得、URL基準の相対import、キャッシュ、取得失敗の扱い |

当時、次のインクリメントの第一候補は外部コマンドだった。現在は標準ライブラリ導入により、外部コマンドは`child_process`から利用できる。

当時はストリーミングをファイル・HTTPクライアントから始め、HTTPサーバーを別段階にする案だった。現在は標準ライブラリのWeb StreamsとFetchから利用できる。import mapとHTTP importは関連するが、別インクリメントとして仕様を確かめる案とする。

## 保留と製品方針

暗号・ハッシュは当時は要検討だった。現在はWeb Cryptoと`crypto`モジュールから利用できる。

TypeScript対応は引き続き後回しとする。npm・パッケージ管理とNode.js/Denoの完全互換は対象外とする。Web APIとNode形式APIは固定したgo-quickjs標準ライブラリの互換範囲に従う。
