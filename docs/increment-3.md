# NOE インクリメント3 行編集ライブラリ導入計画

> この文書は実装当時の計画・検証記録です。現在の仕様は[APIリファレンス](api.md)と[stdlib移行記録](increment-12.md)を参照してください。旧`noe.*` API、独自I/O実装、当時の対象外・中断動作は現行仕様ではありません。

インクリメント3では、REPLにGoの行編集専用ライブラリを導入する。カーソル移動や入力の修正をライブラリに任せ、後続の履歴保存・補完・複数行入力を組み込める入力処理を作る。

状態は全スライスの実装・レビュー・総合E2E完了。前提は[インクリメント2](increment-2.md)の完了したREPL。次の[インクリメント4](increment-4.md)はREPLの操作性改善をテーマとする。

## 対象範囲

- 端末でのREPL入力に行編集ライブラリを使う。
- 左右移動、Home/End、Backspace/Delete、基本の単語移動・削除を使えるようにする。
- ライブラリが提供するセッション内履歴を使い、前の入力を呼び出して修正・再実行できるようにする。
- 端末入力とパイプ・ファイル入力を分け、後者には現在の行読み取りを使う。
- EOF、明示終了、Ctrl+Cと端末設定の復元を既存のCLIへ接続する。
- 入力処理とJS評価を分け、後続の改善を入力側へ追加できるようにする。

履歴の永続化、JSのTab補完、複数行入力、前回結果の`_`、Ctrl+Cで評価だけを中断して続行する操作はインクリメント4で扱う。Bubble Tea、画面分割、独自の端末エディタは今回導入しない。ライブラリ標準の履歴検索などを、範囲を分けるためだけに無効化することはしない。

JavaScriptの評価仕様、ホストAPI、TypeScriptの延期、npm・Node/Deno互換を実装しない製品方針は引き継ぐ。

## ライブラリの選定

候補は[github.com/chzyer/readline](https://github.com/chzyer/readline)と[github.com/peterh/liner](https://github.com/peterh/liner)。両方とも純Goで、行編集・履歴・補完の仕組みを提供する。`chzyer/readline`から調査を始めるが、採用順位を確定した意味ではない。

スライス1で実際の端末と現在のCLIに接続する小さな検証を行い、採用ライブラリとバージョンを決める。READMEの機能一覧だけでは選定を完了扱いにしない。

### 必須の選定基準

現在の利用環境はGo 1.27.2、Linux amd64の端末。NOE全体のGo要件を1.27.2へ揃える。まずこの環境と既存のCLI契約に適合することを採用条件とし、未検証のOSまで対応済みとは扱わない。

| 基準 | 採用に必要な確認 |
| --- | --- |
| Goの実装とビルド | 現行のGo要件で利用でき、CGO無効でCLIをビルドできる。JSエンジンの変更を必要としない |
| 基本の編集 | 左右移動、Home/End、Backspace/Delete、単語移動・削除、セッション内履歴が使える |
| 日本語と表示 | 日本語を含むJS文字列を入力・途中編集・評価できる。端末幅を超える入力でカーソルと再描画が崩れない |
| 割込みと終了 | 入力待ち、無限ループのJS評価、HTTP待ちで、PTYに送った実際のCtrl+Cのキー入力がコード130で終了する。EOFと明示終了も既存のコードを維持する |
| 端末の復元 | EOF、明示終了、割込み、入力失敗の後で、端末設定を元に戻せる |
| 入出力への接続 | 既存のstdin・stdout・stderrへ接続でき、通常ログと診断の出力先を維持する。非端末入力では既存の行読み取りへ切り替えられる |
| 次の改善への接続 | プロンプトを変更でき、補完候補の取得処理を接続でき、履歴の取得・追加または保存を扱える。JSの操作を評価側のgoroutineに残せる |
| 依存の再現性 | 採用バージョンとライセンスを確認し、依存を固定して再ビルドできる |

ライブラリが単独でNOEの終了契約を実装する必要はない。小さなアダプターで契約を満たせることを確認する。ライブラリ内部のfork、独自の端末エディタ、JSエンジンの改造が必要なら、その候補の接続方法を見直す。

### 条件を満たす候補の比較

必須条件を満たす候補について、次の優先順で比較する。スター数や機能数だけでは決めない。

1. 現在のCLIへ接続するコードが少なく、端末設定と割込みの所有者が明確であること。
2. インクリメント4の履歴保存、継続プロンプト、補完、中断後の続行へ公開APIで接続できること。
3. 実際に必要となる依存と保守対象が小さいこと。直近の変更、関連する未解決issue、ライセンス、固定できるバージョンを確認する。更新日の新しさだけを合否にしない。

### 比較結果の記録

スライス1では両候補を同じ操作で検証する。入力例、キー列、端末幅、候補のバージョン、期待する結果を揃え、Ctrl+CはOSシグナルの送信だけでなくPTYへのキー入力で確認する。パイプ入力の回帰確認と端末設定の復元も記録する。

各必須基準について「適合・不適合・未確認」を記録し、確認方法と必要なアダプターを添える。採用理由、比較候補を選ばなかった理由、残る制約、直接・間接依存をこの計画に追記する。未確認を適合扱いにせず、両候補が適合する場合も上の比較基準で選ぶ。

比較スパイクでは、`chzyer/readline v1.5.1`と`peterh/liner v1.2.3`を既存Sessionへ接続し、Go 1.27.2・CGO無効のビルドで両候補とも共通28シナリオに適合した。現在のLinux CLIでは、終了・入力エラーの契約に合わせる追加処理の少なさから`peterh/liner v1.2.3`を選定した。Go 1.27.2を基準とするため、Go 1.26を要求するv1.2.3を採用できる。

候補ごとのアダプター、比較設定、依存、確認した範囲と制約は[比較結果](repl-lineedit-spike.md)を参照する。スライス2では、実際の標準入出力fd 0・1にlinerを接続し、差し替えたReader/Writerと非端末入力には既存の行読み取りを使う。

## 入力と終了の契約

| 項目 | 動作 |
| --- | --- |
| 対話入力 | 標準入力と標準出力が端末の場合、行編集を使う。端末を制御できない場合は通常の行読み取りへ戻す |
| パイプ・ファイル入力 | 端末制御用のエスケープシーケンスを出さず、現在の行読み取りと`> `表示を維持する |
| 評価 | Enterで確定した1行を既存のSessionへ渡す。空行は評価しない |
| 履歴 | 対話セッション内で入力を呼び出せる。ディスクへの保存は次のインクリメントで導入する |
| EOF | 空の対話入力でCtrl+Dを押すとコード0で終了する。パイプの改行なし最終入力も評価する |
| 明示終了 | `noe.exit(code)`は指定コードで終了する |
| Ctrl+C | 入力待ち・JS評価中・HTTP待ちのいずれでもセッション全体をコード130で終了する |
| 後始末 | 通常終了、入力失敗、明示終了、割込みの各経路で端末設定を復元する |

Ctrl+Dなどの編集中のキーは採用ライブラリの標準操作を使い、READMEに実際の操作を記載する。インクリメント3では終了の意味を変えず、インクリメント4で中断と終了を分ける。

## 実装方針

`internal/cli`に、行読み取りと終了処理だけを提供する小さな入力アダプターを置く。端末用の実装は採用ライブラリを包み、非端末用の実装は既存の`bufio.Reader`による読み取りを使う。汎用のTUIフレームワークや差し替え用プラグイン機構には広げない。

入力アダプターはJSランタイムやJSの値を持たない。Sessionの生成・評価・結果表示は現在の評価ループに残し、ライブラリ内部のgoroutineからエンジンを呼ばない。

端末のraw modeではCtrl+CがOSのシグナルにならず、入力キーとして届く場合がある。入力待ちでライブラリが返す割込みと、評価中に受け取る割込みを、既存のセッションキャンセルへ接続する。評価中に通常の端末モードへ戻す方式も含め、スライス1で選んだライブラリの動作に合わせて決める。

入力の先読みがあっても、JS評価と次の入力の評価は順番に行う。`console.log`などの出力と端末描画の経路を整理し、現在の標準出力・標準エラーの区別を維持する。

## スライス1 ライブラリ選定と端末検証

両候補を小さな検証プログラムに接続し、必須の選定基準を同じ操作で確認する。基本の編集、履歴、日本語入力、長い行の折り返し、EOF、割込み、評価中の出力、端末設定の復元を確認する。

完了条件は、両候補の比較結果と既存の終了契約を維持する接続方法を示し、採用ライブラリと固定バージョンを記録すること。一方の候補が実装上の理由で必須条件を満たせない場合は、その根拠を記録し、残りの操作検証を省略できる。

## スライス2 入力アダプターとREPL接続

端末と非端末の入力を分け、行編集を`noe repl`へ組み込む。ライブラリの割込み・EOF・読み取りエラーを既存の終了処理へ対応させ、全経路で入力処理を閉じる。

完了条件は、前の入力を呼び出して修正・再実行でき、変数保持・非同期評価・エラー後の続行が引き続き動くこと。パイプ入力の出力と終了コードを維持し、JSエンジンを入力側から操作しないこと。

## スライス3 利用説明と総合E2E

READMEに基本キー操作、セッション内履歴、対話入力とパイプ入力の違いを記載する。実際のCLIを使う端末操作の検証と、既存のREPL・ファイル実行を含む総合E2Eを行う。

完了条件は、行の途中を修正して評価でき、履歴から再実行でき、EOF・明示終了・入力待ちと評価中とHTTP待ちのCtrl+Cで期待するコードを返すこと。終了後に端末の入力表示とキー操作が元に戻ること。

## 検証とレビュー

各スライスで受入条件に対応する検証とレビューを行い、必須指摘を解消して次へ進む。スライス1の検証結果は、ライブラリ採用の根拠としてこの計画に追記する。

Goテストは入力モードの選択、エラーと終了状態の対応、既存評価との接続を確認する。ライブラリ内部のキー処理をNOEの単体テストで再実装して検証しない。対話操作はPTYで確認し、非端末のE2Eだけで行編集の完了扱いにしない。

スライスの区切りでは`go test ./...`とCGO無効のビルドを行う。入力goroutineやキャンセル経路を変更した場合は、関連するCLI・runtimeのrace検査を行う。最後に`go test -tags=e2e ./... -count=1 -v`と端末操作の確認を行う。

| スライス | 実装と検証 | レビュー |
| --- | --- | --- |
| 1 | 両候補の比較スパイクを実施。Go 1.27.2でliner v1.2.3を選定し、共通操作とrace検査を再確認 | 旧版比較の批判的レビュー記録と、新版の再検証範囲を[比較結果](repl-lineedit-spike.md)に区別して記録 |
| 2 | 入力アダプターとREPL接続を実装。Goテスト、CLI・runtimeのrace検査、CGO無効ビルド成功 | 通常レビューで必須指摘なし |
| 3 | READMEのキー操作説明とLinuxの製品PTY E2Eを実装。編集・日本語・履歴・割込み・端末復元を確認 | 批判的レビューで必須指摘なし |

端末の設定は、入力中だけ編集用のモードにして、JS評価とホストI/Oの間は通常のモードへ戻す。次の行の読み取りは評価完了後に開始する。JSエンジンは従来の評価ループだけで操作する。

linerはプロセスの標準入出力を使うため、実際のfd 0・1が対応する端末の場合だけ接続する。差し替えたReader/Writer、パイプ・リダイレクト、未対応の端末では既存の行読み取りを使う。履歴は空白だけの入力を除いてセッション内に追加する。

ルートmoduleにもliner v1.2.3を固定した。端末判定には`golang.org/x/term v0.40.0`、Linux PTY E2Eには`golang.org/x/sys v0.48.0`を使う。関連する間接依存は`github.com/mattn/go-runewidth v0.0.31`、`github.com/clipperhouse/uax29/v2 v2.7.0`。

## 総合検証の結果

Go 1.27.2、Linux amd64環境で以下の検証が成功した。未解決の必須レビュー指摘はない。

- `go test ./...`とCGO無効のCLIビルド。
- `go test -race ./internal/cli ./internal/runtime`。
- 製品PTY E2E。入力の途中編集、日本語、長い行、履歴からの修正と再実行、変数保持とエラー後の続行を確認。
- EOF、明示終了、入力待ち・履歴検索・無限ループ評価・HTTP待ちへの実際のCtrl+C、外部SIGINT。終了コードと終了後の端末設定の一致を確認。
- 全スライスのレビュー後の`go test -tags=e2e ./... -count=1 -v`。既存のファイル実行・API・REPLと新しい端末操作の全E2Eが成功。
- `go vet ./...`、`gofmt -l cmd internal tests`、`git diff --check`。指摘・未整形ファイル・空白エラーなし。

PTY E2EはCGO無効でビルドした製品CLIを制御端末付きの別プロセスで実行する。入力エコーとは区別した評価結果を待ち、評価開始ログやローカルHTTPの開始を確認してから割り込む。外部サービスを使わず、Pythonなどの追加ツールも要求しない。

全角文字が右端の残り1列から始まる表示については、比較スパイクに記録した実端末での未確認事項を引き継ぐ。他OSや端末エミュレーターごとの表示まで検証済みとは扱わない。

リポジトリ直下の`noe`も最新ソースからCGO無効でビルド済み。`./noe repl`で行編集とセッション内履歴を試せる。
