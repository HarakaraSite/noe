# Multipart boundaries and text-field newlines

Approved local continuation after `f280741` on 2026-11-08. The selected changes
follow the [API policy](stdlib-api-policy.md),
[MIME delimiter grammar](https://www.rfc-editor.org/rfc/rfc2046#section-5.1.1) and
[HTML multipart encoding](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#multipart-form-data).
No push, publication, installation, service or other-project change is included.

### Scope and migration

The baseline loses field/file bytes when an inline `--boundary` is mistaken for
a delimiter. `before--fixtureafter` becomes `before`. It also sends text-field
LF/CR unchanged instead of CRLF normalization. Both are reproduced in the
`f280741` development binary; Deno 2.9.7 preserves the inline text and normalizes
the outgoing value.

The parser now recognizes delimiter lines at message start or after CRLF, with
normal/closing suffixes and MIME SP/HTAB padding. It ignores preamble/epilogue and
removes only the separator CRLF, preserving file data and trailing line breaks.
Inline markers remain data. Chunk-split inputs, empty fields, duplicate names and
part order continue to work. Non-delimiter/mixed-LF marker occurrences are not
treated as valid framing.

Only outgoing text field values normalize bare CR/LF to CRLF; existing CRLF is
preserved. Serialization does not modify FormData entries, file bytes or Blob
contents. Incoming text is decoded as received, without newline normalization.
Request, Response, native fetch and noe:http use the same implementation.

Field-name/filename escaping, broader MIME header/parameter parsing, malformed
payload rejection and incremental multipart parsing remain outside these two
corrections. The existing body collector, native limits, grants and cleanup are
unchanged. No new signatures, dependencies or compatibility layer are added.
