# noebot migration to NOE's filesystem module

2026-11-06. Preparation for the next NOE release; no release version has been
assigned. Source audit used a fresh read-only clone of remote noebot `main`
at `41fa1527bef60c96f778ea844abcf1044b24069c`. These instructions do not
change or deploy noebot. Recheck the remote revision when applying them.

NOE now follows the [Web standards and NOE host API policy](stdlib-api-policy.md).
The first slice removes `node:fs`, `node:fs/promises`, `fs`, and `fs/promises`
and replaces them with one asynchronous-first `noe:fs` module, retaining
explicit Sync functions. See the [full migration](stdlib-noe-fs.md).

## Required runtime changes

Replace `import fs from 'node:fs'` with `import fs from 'noe:fs'` in:

- `app/config.mjs`
- `app/core.mjs`
- `app/images.mjs`
- `app/main.mjs`
- `app/notes.mjs`
- `app/store.mjs`
- `app/web.mjs`

Change `app/telegram.mjs`'s named `readFile` import from
`node:fs/promises` to `noe:fs`. The audited application uses explicit Sync
helpers and promise `readFile`; their signatures and results are retained.
It has no FileHandle, `fs.promises`, or filesystem-watch migration at this
revision. Keep the current synchronous persistence/rename/flush behavior;
namespace adoption does not require redesigning it.

Migrate imports in NOE-executed `tests/*.mjs` and JavaScript generated by
Python fixtures, including Telegram, image-flow, distribution, runtime,
portability, and Web integration tests. Inspect embedded NOE code in `.cjs`
tests too: `tests/typecheck_gate.cjs` includes a NOE import inside a string.

**Keep actual Node development-tool imports unchanged.** In particular,
`scripts/typecheck.cjs` and `.cjs` test harnesses use `require('node:fs')` while
running under Node. Replacing those with `noe:fs` would break those tools.

## Declarations and release requirements

Update the NOE stdlib declaration source and hash used by
`scripts/typecheck.cjs`; the removed FS declarations are intentionally absent.
Check the companion agentlib declaration hash against the selected NOE source
as well. Its metadata and diagnostic baseline are currently pinned to
v2.14.0 (`d62723041863523283f2d750bd83be9d4feee00e`). Review and migrate
the typecheck metadata/baseline with the new declarations, retaining checks for
new and stale diagnostics. Update `docs/typechecking.md` and NOE fixture imports.

After NOE publishes this change, raise noebot's minimum NOE version to that
release in startup checks, documentation, and fixtures. Update the launcher
and child-process environment together. The migrated noebot source will not
run on the old release because `noe:fs` is new. Do not introduce automatic
fallbacks to the removed modules.

## Checks before rollout

Run noebot's offline filesystem, persistence, core, instructions, image,
Telegram, and conversation suites with the selected NOE executable. Then
run its existing fixture-based runtime/Web/Telegram flows and TypeScript
gate as appropriate. Check both startup and child processes use the same
release. Providers do not need to be contacted for this namespace migration.

Later `noe:process` and HTTP-helper changes are separate decisions. Keep their
current imports until a corresponding migration is specified.
