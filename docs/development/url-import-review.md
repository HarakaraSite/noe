本書は初回設計レビューの記録。後続の利用者指示で4スライスの実装へ進んだ。現在の進捗は[実装記録](url-import-implementation.md)、追加指示に対する計画は[スライス計画](url-import-slices.md)、再レビューは[通常](url-import-plan-rereview-normal.md)・[批判的](url-import-plan-rereview-critical.md)、各sliceの判定は[コードレビュー](url-import-code-review.md)を参照。以下の「今回」は初回の設計検討を指す。

## 結論

[設計案](url-import-plan.md)をファイル化し、通常レビューと批判的レビューを別のレビュアーへ並行して依頼した。両者は他方の結果を読まず、現行コードと利用者合意に照らして独立に確認した。

- 通常レビュー：設計検討・文書化の成果として妥当。重要な修正指摘なし。
- 批判的レビュー：重大・致命的な設計矛盾なし。明文化の指摘2件を受け、正本へ反映。
- 批判的レビューの元担当がC1/C2だけを再確認し、ともに文書設計上クローズ。追加の修正要求なし。

これは実装完了、公開CDNでの利用成立、全技術詳細の確定を意味しない。今回の依頼は設計案の整理・通常/批判的レビューまでであり、その範囲は完了した。

## 残る判断・確認

### レビュー後に解決した利用者判断

- 利用者が「JavaScriptのContent-Typeに加え、text/plainも許す」案を選択した。設計案§2・§7.2と確認計画へ反映済み。
- URL拡張子不問とは別の合意であり、すべてのMIMEを受理する意味ではない。
- 現時点で利用者の判断待ちの利用方針はない。レビュー原文のMIME未決という記述はレビュー時点の記録として保持する。この追記は利用者判断の反映であり、実装・再レビュー済みという意味ではない。

### 技術設計・実装時に詰めるもの

- JavaScript MIME集合、Content-Typeの判定・不備の診断、charset/BOMの処理。
- 標準/custom loaderの有効・無効・不明をHostへ伝える能力metadataの互換API。
- URL正規化、redirect/fragment、canonical IDの具体的規則。
- 固定engineでのURL/alias/redirect/循環のmodule同一性。
- 同期HTTP中、ヘッダー待ち・本文待ちから実行contextで取消せること。
- 仮Go APIの命名・配置、HTTP共通処理の再利用範囲。
- 選定した公開ESMを実際に取得し、exportを利用できること。

これらは今回発見した既存製品の不具合ではない。未実装機能の残る判断・確認であり、レビュー完了を理由に動作保証済みとはしない。

## 変更・検証範囲

変更したのは設計案、レビュー記録3件、開発文書索引のみ。製品コード、既存API、バイナリは変更していない。

レビューは関連現行コードと固定engineの契約を読む静的な設計レビュー。外部CDNへの接続、製品テスト・ビルド、実providerの呼出し、engineスパイクは実施していない。文書の参照先と差分の整合だけを親が確認する。

利用者の合意を超えてキャッシュ、lockfile、npm探索、TypeScript変換、権限昇格API等を追加していない。
