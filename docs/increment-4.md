# NOE インクリメント4 REPL操作性改善テーマ

インクリメント4では、[インクリメント3](increment-3.md)で導入した行編集ライブラリを使い、スクリプトを繰り返し試す操作を改善する。履歴保存、JSの補完、複数行入力、評価の中断と続行を中心に扱う。

状態はテーマ決定。採用ライブラリとインクリメント3の実装結果を踏まえて、着手前に操作の契約・実装スライス・受入条件を具体化する。

## 改善する操作

| 項目 | 目指す動作 |
| --- | --- |
| 履歴保存 | REPLを起動し直しても前の入力を呼び出せる。保存先、保存を無効にする方法、書き込み失敗時の動作を定める |
| Tab補完 | キーワード、利用できるグローバル名、REPLで宣言した名前、オブジェクトのプロパティを補完する |
| 複数行入力 | 関数・オブジェクトなどの未完の入力を保持し、`... `で続きを入力できる |
| 前回の結果 | `_`で直前に成功した評価の結果値を参照できる |
| 入力の中止 | Ctrl+Cで編集中の入力や複数行の入力を破棄し、プロンプトへ戻る |
| 評価の中断 | Ctrl+Cで実行中のJSやHTTP待ちを中断し、セッションを続けられる |
| 終了の案内 | 中断とプロセス終了を区別し、EOF・明示終了を含む操作をhelpとREADMEで説明する |

履歴検索は、採用ライブラリの機能を利用する。既に使える場合はインクリメント3から使い、インクリメント4では保存した履歴との接続を確認する。

## 優先順とスライスの候補

1. 履歴の永続化と`_`を追加し、直前の作業を繰り返しやすくする。
2. 未完の入力をまとめて評価する複数行入力を追加する。
3. 入力中止と評価中断を分け、Ctrl+C後に同じセッションで続行できるようにする。
4. JSのTab補完と候補表示を接続する。
5. 利用説明を更新し、実際の端末操作と既存CLIを含む総合E2Eを行う。

複数行入力で使う入力の破棄操作はスライス2から用意し、スライス3で実行中断も含めたCtrl+Cの動作に統合する。各スライスでは実装・目的に対応するテスト・レビューを行う。

## 詳細計画で決めること

複数行入力は、JSエンジンの構文確認を使って、続きを待つ入力と確定した構文エラーを区別する。同期入力の継続と、現在の限られた`await`変換の対応範囲を分けて定める。複数行を受け付けることだけを理由に、非同期の分割代入や任意の複数文変換まで対応済みとしない。

Ctrl+Cによる続行では、セッション全体のcontextと1入力のcontextを分ける。現在のキャンセルでSessionが終了する経路を見直し、実行・I/O・ジョブ・結果整形を止めた後に、次の評価へ戻れることを確認する。中断前の変数変更やファイル書き込みを巻き戻す仕様にはしない。前の入力のI/Oや診断が次の入力へ混ざらない終了手順を定める。

補完は、候補を取得する処理をJSランタイムの所有goroutineで実行する。行編集ライブラリのコールバックから直接エンジンを操作しない。プロパティ補完でgetterを呼ぶか、プロパティの記述情報だけを使うかを決め、実行中の評価と補完を重ねない。

履歴は、追加のDBを導入せず、採用ライブラリの保存機能またはテキストファイルを基本案とする。複数行の入力を1件として保存・再表示できる形式を決める。

## このテーマに含めない機能

画面分割、変数一覧の常時表示、マウス操作、組み込みの全画面エディタは含めない。Bubble Teaの導入は、このテーマの前提にしない。構文の色分け、テーマ、Undo/Redoの独自実装、自動インデントは必要に応じて別途検討する。採用ライブラリが既に提供する機能を取り除く意味ではない。

TypeScript、npm・Node/Deno互換、Web標準への全面互換、静的importのREPL対応、非同期入力の一般的なソース変換へは広げない。
